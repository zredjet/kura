# 検索クエリ言語と ⌘K パレット

検索欄・⌘K パレット・スマートフォルダ・スマートプレイリストの条件は、すべてこの言語で書きます。
実装は `crates/kura-core/src/query/`（字句解析 → 構文解析 → AST → SQL）。AST は JSON にしてスマートプレイリストの `rule_json` に保存します。

## 1. 書き方の例

| 入力 | 意味 |
|---|---|
| `夕景` | タグ「夕景」が付いている（同名タグがなければ名前・メモ・URL の全文検索） |
| `夕景 海` | 「夕景」かつ「海」 |
| `海 \| 港` | 「海」または「港」 |
| `-未整理` | タグ「未整理」が付いていない |
| `作者:もりの` | 名前空間付きタグ |
| `種類:動画` | 動画だけ |
| `種類:画像,動画` | 画像または動画 |
| `評価>=4` | 評価 4 以上 |
| `長さ>3分` | 3 分より長い |
| `追加:7日以内` | 7 日以内に追加 |
| `再生:未` | 一度も再生していない |
| `フォルダ:"写真/2026 旅行"` | そのフォルダか子孫フォルダにある（空白を含む値は引用符で囲む。ADR-52） |
| `ユニット:なし` | どのユニットにも属さない |
| `"駅前 夜"` | 空白を含む語（同名のタグがあればそのタグ、なければそのまま全文検索） |
| `"Re:ゼロ"` | `:` や空白を含む、名前空間なしのタグ（引用符で囲まないと「Re」という名前空間として読む） |
| `(海 \| 港) 評価>=3 -ラフ` | かっこでまとめる |

## 2. 文法

```text
query      := or_expr
or_expr    := and_expr ( WS? "|" WS? and_expr )*
and_expr   := unary ( WS unary )*
unary      := "-" atom | atom
atom       := "(" query ")" | field_expr | term
field_expr := FIELD op VALUE
op         := ":" | "=" | ">" | ">=" | "<" | "<=" | "!="
term       := QUOTED | WORD                 # WORD に ":" を含めば「名前空間:名前」
```

- `FIELD` は §3 の表にある名前（日本語・英語どちらも可）。`作者:もりの` のように、`:` の左がフィールド名でなければ名前空間付きタグとして扱う。
- `term` の判定順：①タグの別名 → ②正式タグ（名前空間なし）→ ③どちらでもなければ全文検索。引用符で囲んだ語（`QUOTED`）も同じ順で判定する（ADR-127）。
- 優先順位は `-` > 空白（AND）> `|`（OR）。
- 空白を含む値は引用符で囲む（`フォルダ:"写真/2026 旅行"`、`作者:"もりの 森"`）。値の引用符は記号のすぐ後ろに続ける。パレットの候補から選ぶと自動で囲む（ADR-52）。
- `-` は語の先頭（空白・かっこ・`|` の後）にあるときだけ除外。`IMG-001` の `-` は語の一部。
- フィールド名の英語は大文字小文字を問わない（`TYPE:video`）。
- 全角の `｜`、`－`、`＞`、`＝`、`：` も半角と同じに扱う。ほかに `＜`・`！`・全角のかっこ・`“”＂`（引用符）・U+2212 の `−`（`-`）・読点 `、` と全角の `，`（`,`）・全角の空白も同じ（表は `query::SYMBOLS`。引用符の中は直さない）。フロントのチップの読み方（`clauses.ts`）と候補（`query_suggest`）も同じ表を使う。
- 解析エラーは位置と理由を返し、パレットはその位置に下線を引く。

## 3. フィールド

| 日本語 | 英語 | 型 | 値の例 | 備考 |
|---|---|---|---|---|
| 種類 | type | 列挙 | 画像 / 動画 / 音楽 / フォント / 3D（image / video / audio / font / model） | `,` で複数（読点 `、`・全角の `，` も `,` と同じ。字句解析で直す） |
| 評価 | rating | 整数 0–5 | `評価>=4`、`評価:0`（未評価） | |
| 長さ | dur | 時間 | `30秒`、`3分`、`1時間`、`1:30` | 画像は対象外 |
| 追加 | added | 日付 | `今日`、`昨日`、`7日以内`、`30日以上前`、`2026-10`、`2026-10-01..2026-10-08` | |
| 撮影 | taken | 日付 | 同上 | 撮影・投稿日時 |
| 再生 | played | 日付 / 未 | `再生:未`、`再生:30日以上前` | |
| 再生回数 | plays | 整数 | `再生回数:0` | |
| フォルダ | folder | パス | `写真/2026 旅行`（`/` 区切り） | `:` は子孫を含む、`=` はそのフォルダだけ |
| ユニット | unit | 名前 / あり / なし | `ユニット:鎌倉`、`ユニット:なし` | |
| 取得元 | source | サイト名 | `pixiv`、`youtube`、`capture`、`local` | |
| 名前 | name | 文字列 | `名前:IMG_` | タイトルと元ファイル名 |
| URL | url | 文字列 | `url:example.com` | |
| メモ | note | 文字列 | `メモ:構図` | |
| タグ数 | tags | 整数 | `タグ数:0` | |
| 幅 / 高さ | w / h | 整数（px） | `幅>=3000` | |
| 向き | orient | 列挙 | 縦 / 横 / 正方形 | |
| 透過 | alpha | 列挙 | あり / なし / 半透明 / 二値（`あり` は二値か半透明） | 画像。解析の事実。JPEG・HEIC・HEIF は読まずに形式から「なし」 |
| ドット絵 | pixel | あり / なし | `ドット絵:あり` | 画像。実効値「素材の設定 ?? 自動の判定（v1）」で比べる |
| 色数 | colors | 整数 | `色数<=16`、`色数>256`（256 より多いもの） | 画像。解析の事実。JPEG・HEIC・HEIF は計らない。事実は 257 で打ち切る（257 は「256 より多い」で、数は計っていない。§4） |
| 2のべき乗 | pot | あり / なし | `2のべき乗:あり`（`２のべき乗` も可） | 画像の幅と高さがどちらも 2 のべき乗。解析は要らない（幅・高さから求める） |
| レート | rate | 整数（Hz） | `レート:44100`、`レート:44.1k`、`レート>=48kHz` | 音声。解析の事実 |
| ビット | bits | 整数 | `ビット:24`（`24bit` も可） | 音声。解析の事実。非可逆の形式は計れない |
| チャンネル | ch | 整数 / モノラル / ステレオ | `チャンネル:ステレオ`、`チャンネル>2` | 音声。解析の事実 |
| ラウドネス | lufs | 実数（LUFS） | `ラウドネス>-14`、`ラウドネス<=−23.5` | 音声の積分ラウドネス。解析の事実。大小の比較だけ |
| ピーク | peak | 実数（dBTP） | `ピーク>-1` | 音声のトゥルーピーク。解析の事実。大小の比較だけ |
| ループ | loop | あり / なし | `ループ:あり` | 音声のループ点。解析の事実 |
| アニメ | anim | あり / なし | `アニメ:あり` | 画像のコマが 2 つ以上。解析の事実（コマの数だけを見て、素材の格子の設定は見ない）。JPEG・HEIC・HEIF は形式から 1 コマ（`アニメ:なし`） |

- 表の正本は Rust の `query::FIELDS`（`crates/kura-core/src/query/fields.rs`）。フロントは bindings の定数 `QUERY_FIELD_NAMES`
  （フィールドの名前）・`QUERY_KIND_WORDS`（種類の語）・`QUERY_SYMBOLS`（半角と同じに扱う記号）を読み、チップやスマートの
  ルールの行で「フィールドの条件か、名前空間付きのタグか」を Rust と同じに見分ける（M11）。
- 素材のフィールド（M11）を足したので、`透過`・`ドット絵`・`色数`・`レート`・`ビット`・`チャンネル`・`ラウドネス`・`ピーク`・
  `ループ`・`アニメ`（と英語名）を名前空間にしたタグは、`アニメ:進撃` のような書き方では探せない（フィールドとして読む）。

## 4. AST（JSON の形）

```json
{ "and": [
  { "tag": { "ns": "", "name": "夕景" } },
  { "or": [ { "field": "type", "op": "has", "value": ["image", "video"] } ] },
  { "not": { "tag": { "ns": "", "name": "未整理" } } },
  { "field": "rating", "op": "ge", "value": 4 }
] }
```

- AST は Rust の enum（`serde` の externally tagged）で定義し、tauri-specta で TS 型も出す。
- 日付の相対指定（`7日以内`）は AST では相対のまま保存し、評価するときに現在時刻で解決する（スマートフォルダが日々更新されるように）。
- 記号は `:` が `has`、`=` が `eq`、`!=` が `ne`、`>` `>=` `<` `<=` が `gt` `ge` `lt` `le`。`:` と `=` を分けるのは、`フォルダ:`（子孫を含む）と `フォルダ=`（そのフォルダだけ）、ユニット単位の `種類:`（含む）と `種類=`（だけ）を区別するため（ADR-51）。アイテム 1 件に対しては、ほかのフィールドでは `has` と `eq` は同じ。
- 日付の値（ADR-57）：`今日`・`昨日`・`2026`・`2026-10`・`2026-10-01`・`A..B` は端末の時差での日付で区切った期間。`7日以内` は今から 7×24 時間以内、`30日以上前` は 30×24 時間より前。`:` `=` は期間の中、`!=` は期間の外（日付がないものを含む）、`>` は期間の終わり以降、`>=` は始まり以降、`<` は始まりより前、`<=` は終わりより前。
- 値の書き方：長さは `30秒`・`3分`・`1時間`・`1時間30分`・`90s`・`1:30`・`1:02:03`（数だけなら秒）。種類は `画像`・`動画`・`音楽`・`フォント`・`3D`（`image`・`video`・`audio`・`font`・`model`。`3D` と英語は大文字・小文字を問わない）を `,` で複数（`種類:フォント`・`種類:3D`・`type:font`・`type:model`）。AST の値は `items.kind` と同じ英語名。スマートプレイリストはフォント・3D を候補にしない（playlists.md §1.1）。向きは `縦`・`横`・`正方形`（幅と高さの差が 1% 以内）。ユニットは名前・`あり`・`なし`。
- 素材のフィールドの値（M11）：
  - あり・なしのフィールド（ドット絵・2のべき乗・ループ・アニメ）は `あり`・`なし`（`はい`・`いいえ`、`yes`・`no`、`true`・`false` も可）。AST の値は `true`・`false`。
  - 透過は `あり`・`なし`・`半透明`・`二値`（`yes`/`any`・`no`/`none`・`partial`・`binary`）。AST の値は `"any"`・`"none"`・`"partial"`・`"binary"`。事実の値（0 なし・1 二値・2 半透明あり）と、`あり` は 1・2、`なし` は 0、`二値` は 1、`半透明` は 2 で比べる。
  - あり・なしのフィールドと透過は、大小の比較（`>` など）を断る。`!=` は「わかっていて違う」（`透過!=あり` は透過なしと分かっているもの）。
  - レートは Hz の整数。`44.1k`・`48kHz`・`96000Hz` も受け、Hz にして端数の出るもの（`44.1005k`）と 0 以下は断る。ビットは 1 以上（`24bit` も可）。チャンネルは 1 以上の数か `モノラル`（1）・`ステレオ`（2）。色数は 0 以上の整数。
  - ラウドネス（LUFS）・ピーク（dBTP）は 10 進の数（符号は `-`・`+`・U+2212 の `−`。単位 `LUFS`・`dBTP`・`dB` を付けてもよい）。大小の比較だけを受け（`ラウドネス:-14` は断る。実数なので一致では探さない）、AST では 1/1000 の整数（`-14.2` → `-14200`。小数第 4 位を四捨五入し、5 以上なら絶対値を 1 上げる（0 から遠い方へ）：`-23.0004` → `-23000`、`-23.0005` → `-23001`）にする。指数・`inf`・`NaN` と ±1000 を超える値は断る。
  - 例：`{"field":"alpha","op":"has","value":"any"}`、`{"field":"pixel","op":"has","value":true}`、`{"field":"lufs","op":"gt","value":-14000}`、`{"field":"rate","op":"ge","value":44100}`、`{"field":"ch","op":"has","value":2}`。値の誤りは、エラーの位置を値の範囲にする。
- **まだ解析していないもの・計れない値**（M11）：解析の事実で決まるフィールド（透過・ドット絵・色数・レート・ビット・チャンネル・ラウドネス・ピーク・ループ・アニメ）は、事実がない（まだ解析していない）ものと計れない値（NULL。短くてラウドネスを計れない・非可逆でビットがない・JPEG の色数など）を、`:`・`=`・`!=`・大小の比較のどれにも一致させない。除外（`-透過:あり`）は補集合なので、これらを含む。日付の欄（`!=` が日付のないものも含む）とは扱いが違う。色数の打ち切り（事実の 257 =「256 より多い」）も数としては比べず、256 より多いどの数でも結果が同じになる比較だけに入れる：`>` と `!=` は 256 以下の値と（`色数>256`・`色数>16`・`色数!=16`）、`>=` は 257 以下の値と（`色数>=257`）。ほかの比較・一致（`色数<1000`・`色数<=257`・`色数:257`・`色数!=300`・`色数>=300`）には、計れない値と同じに入れない（除外は含む。M11 の検証 Q2）。ドット絵は素材の設定があれば、解析の前でも設定の値で決まる。2 のべき乗は幅・高さで決まり、幅・高さがわからないものはどちらにも入らない。
- **未解析の件数**：検索の条件が解析の事実を使うとき、⌘K パレットは「未解析 N 件」を出す（§6）。N は、開いている一覧の中で解析がまだのもの（`analysis_state = 'pending'`）のうち、事実を知らないものとしたときに「一致しうる」が「必ず一致する」ではないもの（解析が終わると一致が変わりうるもの）の数。事実の条件を、否定の中かどうかに応じて「その事実を持ちうる種類か」（一致しうる側）と「偽」（必ず一致する側）に置き換えて数える（`種類:音楽 透過:あり` は 0、`-透過:あり` は未解析の画像の数）。

## 5. SQL への変換

- 全体を `SELECT i.id FROM items i WHERE i.trashed_at IS NULL AND (…)` に変換する。
- タグ条件は `EXISTS (SELECT 1 FROM item_tags t WHERE t.item_id = i.id AND t.tag_id IN (…))`。親タグは子孫タグ ID に展開してから入れる。
- AND の中のタグ条件が 2 つ以上なら、`i.id IN (SELECT item_id FROM item_tags WHERE tag_id IN (…) INTERSECT SELECT …)` にまとめて先に絞り込む（親タグの展開があっても条件ごとに集合を取れるので `GROUP BY … HAVING` ではなく `INTERSECT` にした。10 万件でタグ 3 つの AND が 1ms 未満）。
- 名前空間なしの語は、別名 → 名前空間なしの正式タグ（大文字小文字は問わない）の順に探し、なければ全文検索。名前空間付きの語でタグが見つからなければ一致なし。
- 全体の条件は一覧の種類（すべて・フォルダ・ユニット・スマートフォルダなど）の条件に AND で重ねる（ADR-53）。ゴミ箱の中を検索するときは `i.trashed_at IS NOT NULL` の側に重ねる。
- 全文検索は 3 文字以上なら `i.id IN (SELECT rowid FROM items_fts WHERE items_fts MATCH ?)`、1〜2 文字なら `LIKE`。
- 解析の事実の条件（M11）は `i.hash IN (SELECT b.hash FROM media_facts f JOIN blobs b ON b.id = f.blob_id WHERE …)`（部分索引から集合を作る。相関した EXISTS にしない。docs/data-model.md §4）。同じ AND の中の事実の条件（ドット絵を除く）は 1 つの部分問い合わせにまとめ（事実の行は中身ごとに 1 行なので同じ意味）、その AND の種類の条件は `+i.kind`（種類の索引に引っ張られないように）にする。ドット絵は `(設定が v) OR (自動の判定が v AND 設定がない)`。2 のべき乗は `i.width & (i.width - 1) = 0` のビット演算。あり・なしの列（`has_loop`・`pixel_art`）は、部分索引（`WHERE x = 1`）を使えるよう定数を SQL に書く（利用者の値ではない）。
- 値は必ずバインド変数にする。
- ユニット単位のスマートプレイリストでは同じ AST をユニットの集計値で評価する（`docs/playlists.md` §4.2）。こちらは SQL ではなく、候補を読み込んでから Rust で評価してよい（ユニット数は多くても数千）。

## 6. ⌘K パレットの動き

| 操作 | 動き |
|---|---|
| 入力 | 確定した語はトークン（チップ）になる。最後の語は入力中として候補を出す |
| Tab / → | 選択中の候補を確定 |
| ↑ / ↓ | 候補を移動 |
| ↵ | 今の条件で絞り込んで閉じる |
| ⌘↵ | スマートフォルダとして保存（名前を入力） |
| ⇧↵ | 結果をランダム再生（`play_queue` の `view`。開いている一覧の中で条件に合うものを重み付きでシャッフル。まとめて表示したユニットはユニット単位。ADR-55 で M6 まで出さなかった） |
| ⌫（空欄で） | 最後のトークンを外す |
| esc | 閉じる |

- 候補の順：入力中の語に一致するタグ（使用数の多い順）→ フィールド名 → 保存済みの検索。`フィールド:` まで入力していれば、そのフィールドの値（種類・取得元・フォルダのパス・ユニット名・日付の書き方など）。
- 確定したチップは、解析した「いちばん外側の AND の条件」1 つずつ（`海 | 港` は 1 つ）。スペースを押したとき、入力が完結していれば（引用符・かっこが閉じている）チップにする。
- ↵ は、↑↓ で候補を選んでいればその候補を確定、選んでいなければ絞り込んで閉じる（ADR-60）。
- 保存済みの検索を選ぶと、そのスマートフォルダを開く。
- 入力のたびに `query_parse` で件数を出す（50ms のデバウンス）。「一致 186 項目 — 画像 142 · 動画 44」。
- 解析の事実を使う条件で、まだ解析していないため一致が決まっていないものがあれば、件数の行の右に「未解析 N 件」（`QueryCheckDto.unanalyzed`。0 なら出さない。数え方は §4）。検索の条件に合うものがない一覧では、空の案内を「未解析の N 件は、解析が終わると一致することがあります」にする（M11。design.md §3.1）。
- 比較だけのフィールド（ラウドネス・ピーク）の候補は `ラウドネス>=` の形で入れ、書き方の例（「例：ラウドネス>=-14」）を添える。素材のフィールドの値の候補：透過は あり・なし・半透明・二値、あり・なしのフィールドは あり・なし、色数は 16・64・256、レートは 44.1k・48k・96k、ビットは 16・24・32、チャンネルは ステレオ・モノラル。
- 除外トークンは点線の枠で表示する（デザインモック「検索パレット」参照）。

## 7. テストすること

- 例（§1）すべての解析結果
- 全角記号の正規化
- 名前空間タグとフィールドの区別（`作者:もりの` と `種類:動画`）
- かっこと優先順位（`a b | c` は `(a AND b) OR c`）
- 解析エラーの位置
- SQL 変換後の結果が、ダミーデータで期待どおりの件数になること
- 素材のフィールド（M11）
