# ユニットとプレイリスト仕様

この文書は、ユニット（管理単位）・プレイリスト・シャッフル・再生の仕様の正本です。
実装は `crates/kura-core/src/unit/` と `crates/kura-core/src/playlist/`（純粋関数）、`src/features/playlists/`、`src/features/player/` に置きます。

---

## 1. 用語

| 用語 | 意味 |
|---|---|
| アイテム | ライブラリ内の 1 ファイル（画像・動画・音楽） |
| ユニット（管理単位） | 複数のアイテムを「ひとまとまり」として扱うもの。`set` と `folder` の 2 種類 |
| set ユニット（ファイル群） | 明示的に選んだアイテムの順序付きリスト。中身は静的 |
| folder ユニット（フォルダ群） | 1 つ以上の仮想フォルダを参照するユニット。中身はフォルダの内容に追従する（動的） |
| エントリ | プレイリストに入っている 1 行。種類は `item` / `unit` / `folder` |
| 単位（granularity） | プレイリストの扱い方。`file`（ファイル単位）または `unit`（ユニット単位） |
| キュー | 再生する順番に並べたアイテムの列。プレイリストから生成する |
| スロット | キューの 1 要素（どのアイテムを、どのエントリ・ユニットの一部として、何秒表示するか） |

### 「管理単位」の具体例

- pixiv の複数ページ作品（p0〜p9）→ 10 枚で 1 ユニット
- アルバム 1 枚分の音楽ファイル → 1 ユニット
- 旅行フォルダ「2026 旅行 / 鎌倉」→ フォルダを参照する 1 ユニット
- 「好きなライブ映像」のフォルダ群（複数フォルダ）→ 1 ユニット
- 手で選んだ 5 ファイル（画像 3 枚＋BGM 2 曲）→ 1 ユニット

## 2. ユニット

### 2.1 属性

| 属性 | 型 | 既定値 | 説明 |
|---|---|---|---|
| name | text | 必須 | 表示名 |
| kind | `set` / `folder` | 必須 | 作成後は変更不可 |
| cover_item_id | item? | 先頭メンバー | 表紙 |
| order_mode | `manual` / `name` / `imported` / `captured` / `duration` | set: `manual`、folder: `name` | メンバーの並び順。`name` は自然順ソート（「2」<「10」） |
| order_reverse | bool | false | 並び（`order_mode` で決めたもの）を逆にする（§2.2） |
| inner_shuffle | bool | false | 再生時にユニット内をシャッフルするか |
| image_duration_ms | int? | なし | このユニット内の画像の表示時間（漫画は長め、など） |
| rating | 0–5 | 0 | ユニット自体の評価（0 は未評価） |
| tags | tag[] | なし | ユニット自体に付けるタグ |
| note | text? | なし | メモ |
| origin | `user` / `import` / `download` | `user` | 自動作成かどうか |
| source_url | text? | なし | ダウンロード元（作品ページ・再生リスト URL） |

評価・タグ・メモを変える操作（インスペクタ・1〜5 のキー・タグの欄）は、ユニットを 1 つ選んでも複数選んでも、**ユニット自体とその時点のメンバー全員（ゴミ箱を除く）の両方**に付ける。外すときも両方から外す（メンバーにだけ付いているタグも外れる）。メンバーにも付けたときは「メンバー N 件にも反映しました」と知らせる。ユニット自体の値はユニット単位のスマート条件（§4.2）と集計（§2.4）に、メンバーの値はライブラリの検索とファイル単位の再生に使う。あとから加わったメンバーには付かない。ユニットのインスペクタのタグ欄には、メンバー全員に付いているタグをチップで、一部にだけ付いているタグ（ユニット自体のタグでメンバーにないものを含む）を「3/10」の件数付きで出し、押すと全員に付ける。フォルダへの出し入れとゴミ箱は、もともとメンバーに対して行う（ADR-129）。

### 2.2 メンバーの決め方

- **set**：`unit_items` に登録されたアイテムを `order_mode` で並べる。`manual` のときは `unit_items.pos` の昇順。
- **folder**：`unit_folders` に登録された各フォルダについて、`recursive = true` なら子孫フォルダも含めてメンバーを集め、和集合を取って重複を除き、`order_mode` で並べる。複数フォルダのときは、`unit_folders.pos` の順にフォルダごとに並べてからつなげる。
- 並び順はいずれも昇順：`name` は名前（タイトル）の自然順、`imported` / `captured` は古い順、`duration` は短い順。不明は後ろ、同じなら ID の順。folder ユニットは `manual` を選べない（ADR-45）。
- `order_reverse` なら、上で決めた並び全体を逆にする（folder の複数の参照フォルダは、フォルダの順も逆になる）。一覧・再生・書き出しのすべてで同じ並びを使う。逆にしても表紙は変えない（表紙を選んでいなければ、逆にする前の先頭）。逆順のまま手で並べ替えると、見えている並びのまま逆にして記録する（スイッチを戻すと、その並びの逆になる）。set に加えたメンバーは逆にする前の最後、つまり見えている並びの先頭に出る（ADR-130）。
- ゴミ箱に入ったアイテムは常にメンバーから除く。
- 1 つのアイテムが複数の set ユニットに属してもよい。
- ユニットの中にユニットは入れられない（v1 ではネストなし。階層は folder ユニットの `recursive` で表す）。

### 2.3 作り方

| 方法 | 結果 |
|---|---|
| アイテムを選んで ⌘G「ユニットにまとめる」 | set ユニット（選択順＝manual 順）。名前入力欄を出す（初期値は先頭アイテムの名前） |
| サイドバーのフォルダを右クリック「ユニットとして使う」 | folder ユニット（recursive = true） |
| 取り込みシートの「フォルダごとにユニットを作る」 | 取り込み元の末端フォルダごとに set ユニット（origin = import） |
| gallery-dl で複数ファイルの投稿を取得 | 投稿ごとに set ユニット（origin = download、ページ番号順） |
| yt-dlp で再生リスト URL を取得 | 再生リストで 1 つの set ユニット（設定でオフにできる） |

⌘⇧G「ユニットを解除」は、ユニットを削除するだけでアイテムは残す。

### 2.4 集計値（スマート条件・表示に使う）

| 集計 | 定義 |
|---|---|
| 件数 | メンバー数 |
| 合計時間 | 音楽・動画は `duration_ms` の合計、画像は解決後の表示時間（§5.3）の合計 |
| 種類 | メンバーの種類の集合（`image` / `video` / `audio`） |
| 評価 | ユニットの rating が 1 以上ならそれ。0 なら、評価済みメンバー（1〜5）の平均を四捨五入。評価済みがなければ 0 |
| 最終再生 | このユニットとして再生されたスロットのうち最新の再生日時（§6.4） |
| 追加日 | ユニットの作成日時 |

## 3. プレイリスト

### 3.1 属性

| 属性 | 既定値 | 説明 |
|---|---|---|
| kind | — | `manual`（手動）または `smart`（条件で自動） |
| granularity | `file` | `file`（ファイル単位）または `unit`（ユニット単位）。作成時に選び、後から切り替えられる |
| shuffle | false | シャッフル再生するか |
| shuffle_seed | なし | シード。なしの場合は再生開始時に新しく作る |
| seed_locked | false | true なら同じシードを使い続け、同じ並びを再現する |
| regenerate_on_play | true | smart のみ。再生のたびに条件を評価し直してシャッフルし直す |
| weight_by_rating | true | シャッフル時に評価で重み付けする |
| max_same_kind_run | 2 | 同じ種類が連続してよい最大数。0 は制限なし（§5.4） |
| dedup_items | true | ファイル単位で同じアイテムが複数回出たら最初の 1 回だけ残す |
| image_duration_ms | 8000 | 画像の既定の表示時間 |
| bgm_through_images | true | 画像の間も直前の音楽を流し続ける（§6.2） |
| repeat_mode | `off` | `off` / `all` / `one` |
| rule_json | なし | smart の条件。`{"match":"all\|any","clauses":["検索の文字列", …]}`（各条件は `docs/search-query.md` の文字列。ADR-78） |
| limit_kind / limit_value | なし | smart の上限。`count`（件数）または `duration`（ミリ秒） |
| unit_match | `any` | smart × unit のタグ条件の判定方法（§4.2） |
| include_loose_items | false | smart × unit で、どのユニットにも属さないアイテムを 1 件ずつ候補に含める |
| sort_key / sort_desc | `imported` / true | smart でシャッフルしないときの並び順（追加日・撮影日・名前・評価・長さ・サイズ）（M6） |
| generated_at | なし | smart の並びを最後に作った日時。作った並びはエントリとして保存する（§4.3、ADR-79） |

### 3.2 エントリ（手動プレイリスト）

各エントリは次のどれか 1 つを参照します。

| entry_type | 参照先 | 中身 |
|---|---|---|
| `item` | アイテム | そのアイテム 1 件 |
| `unit` | ユニット | ユニットのメンバー（§2.2）。動的 |
| `folder` | 仮想フォルダ | フォルダの中身。`recursive` フラグあり。名前のない folder ユニットとして扱う。動的 |

エントリは `pos`（REAL）で並べます。間に挿入するときは前後の中間値を使い、差が 1e-9 未満になったらプレイリスト全体の pos を振り直します。エントリごとに `image_duration_ms`（画像の表示時間の上書き）と `start_ms` / `end_ms`（音楽・動画のトリム）を持てます。

### 3.3 単位の違い

| | ファイル単位（file） | ユニット単位（unit） |
|---|---|---|
| 一覧の表示 | ファイルを 1 行ずつ平らに表示。unit / folder エントリは展開して、薄い見出し「〇〇 から」でまとめる | エントリを 1 行ずつ表示。unit / folder の行は表紙・件数・合計時間を出し、▸ で中身を展開できる。item エントリは「単体」として 1 行 |
| シャッフルの対象 | 展開後の全ファイル | エントリ（ユニット）。ユニットの中は順番どおり（`inner_shuffle` なら中だけシャッフル） |
| 「次へ」 | 次のファイル | 次のファイル（ユニットの中を進む）。⇧→ で次のユニットへ |
| 再生中の表示 | 「7 / 42」 | 「ユニット 3 / 12 · 2 / 10」 |
| 重複の扱い | `dedup_items` に従う | 重複除去しない（同じアイテムが別ユニットにあればそれぞれで再生） |
| smart の候補 | アイテム | ユニット（＋ `include_loose_items` なら単独アイテム） |

### 3.4 単位の切り替え（非破壊）

- 切り替えで変わるのは `granularity` の値だけ。**エントリは変更しない**。表示・シャッフル・キュー生成のやり方が変わる。
- 再生中に切り替えたら、今のアイテムを先頭にキューを作り直し、再生位置は維持する。
- 明示的な操作「ファイルに固定」（エントリのメニュー、またはプレイリスト全体）をしたときだけ、unit / folder エントリを、その時点のメンバーの item エントリに置き換える（取り消し可能）。

### 3.5 追加するときの動き

ドラッグ＆ドロップ、「プレイリストに追加」（P）、右クリックのどれでも同じ規則です。

| 追加するもの | ファイル単位のとき | ユニット単位のとき |
|---|---|---|
| アイテム 1 件 | item エントリ | item エントリ（単体） |
| アイテム複数 | item エントリを選択順に追加 | ポップオーバーで選ぶ：「1 つのユニットにまとめて追加」（名前を入力して set ユニットを作成し unit エントリを追加）／「1 件ずつ追加」。前回の選択を既定にする |
| ユニット | 展開して item エントリ（その時点のメンバー） | unit エントリ |
| 仮想フォルダ | 展開して item エントリ（recursive はダイアログの既定値 true） | folder エントリ（動的） |

ドロップ時に ⌥ を押していたら、展開する／しないを逆にします（ファイル単位でもユニットのまま入れられる、など）。

## 4. スマートプレイリスト

### 4.1 ファイル単位

- 候補はゴミ箱以外の全アイテム。条件（`rule_json`）を満たすものを選ぶ。
- 上限が `count` なら N 件、`duration` なら合計時間が上限を超えない範囲で、シャッフル後の先頭から取る（シャッフルなしなら並び順の先頭から）。

### 4.2 ユニット単位

候補は全ユニット（set と folder）。`include_loose_items` が true なら、どのユニットにも属さないアイテムも 1 件ずつ候補に加えます。条件はユニットの集計値（§2.4）で判定します。

| 条件 | ユニットでの判定 |
|---|---|
| タグ（含む） | `unit_match = any`：ユニットのタグ、またはメンバーのどれかにタグがある。`all`：ユニットのタグにある、または全メンバーにある。`unit_only`：ユニットのタグだけを見る |
| タグ（含まない） | 上の「含む」の否定 |
| 種類 | `種類:動画` はメンバーに動画を含む。`種類=動画`（イコール）はメンバーが動画だけ |
| 評価・長さ・最終再生・追加日 | §2.4 の集計値で比較 |
| 名前・URL・メモ | ユニットの name / source_url / note |
| フォルダ | folder ユニットの参照フォルダ、またはメンバーのどれかがそのフォルダにある |

上限の `count` はユニット数、`duration` はユニットの合計時間で数えます。

表にない条件（撮影日・サイズ・向き・取得元・再生回数など）は「メンバーのどれかが一致」で判定します（ADR-80）。

### 4.3 作った並びの保存（M6）

条件を評価して並べた結果は `playlist_entries` に item / unit エントリとして書き出し、画面に「今回の並び」として出します。再生はこのエントリを順番どおりに使います（並びは作ったときに決まっているので、キューを作るときにはシャッフルしない）。作り直すのは「作り直す」・シャッフルの切り替え・並べ直す・条件や設定の変更・エントリがないとき、それに `regenerate_on_play` なら再生のたび（続きからと、一覧の行から再生するときは除く）。詳しくは ADR-79。

## 5. キューの作り方

### 5.1 全体の流れ（純粋関数）

```text
resolve(playlist, snapshot) -> Vec<ResolvedEntry>
build_queue(resolved, options, seed) -> Vec<Slot>
```

- `snapshot` は DB から読んだ必要データ（エントリ、ユニット、フォルダ木、アイテムの種類・長さ・評価・最終再生）を持つ構造体。`resolve` と `build_queue` は DB に触れない。
- `ResolvedEntry { entry_id, unit_key: Option<UnitKey>, items: Vec<ItemId> }`
  - `UnitKey` は `Unit(unit_id)` または `Folder(folder_id, recursive)`。item エントリは `None`。
- `Slot { item_id, entry_id, unit_key, index_in_unit, unit_len, image_duration_ms, start_ms, end_ms }`

### 5.2 手順

1. **解決**：各エントリをアイテム列に展開する（§2.2）。ゴミ箱と、存在しないアイテムは除く。中身が空になったエントリは捨てる。
2. **単位で分岐**
   - **file**：全エントリのアイテムを順につなぐ。`dedup_items` なら最初の出現だけ残す。shuffle なら、この平らな列をシャッフル（§5.4）。
   - **unit**：エントリ（＝グループ）の列を作る。shuffle ならグループ単位でシャッフル（§5.4）。各グループの中は順番どおり、ただし `inner_shuffle` のユニットは中だけシャッフル（§5.5）。最後にグループを平らにつなぐ。
3. **表示時間とトリムの解決**（§5.3）をして Slot にする。
4. **繰り返し**：`repeat_mode = all` の場合、キューの終端で同じシードのまま先頭から（seed_locked でなければ新しいシードで作り直す）。

### 5.3 画像の表示時間

優先順位：エントリの `image_duration_ms` → ユニットの `image_duration_ms` → プレイリストの `image_duration_ms` → アプリ設定の既定値（8 秒）。音楽・動画のスロットでは使わない。

### 5.4 シャッフル

- 乱数生成器は `ChaCha8Rng::seed_from_u64(seed)`。シャッフルの全処理をこの 1 本の乱数列で行い、呼ぶ順番も固定する（同じ入力＋同じシード＝同じ結果）。
- **重み付き**（`weight_by_rating`）：Efraimidis–Spirakis 法。各要素に `u ∈ (0,1]` を引き、キー `u^(1/w)` の降順に並べる。重み `w` は評価から：

  | 評価 | 0（未評価） | 1 | 2 | 3 | 4 | 5 |
  |---|---|---|---|---|---|---|
  | w | 1.0 | 0.6 | 0.8 | 1.0 | 1.5 | 2.0 |

  さらに最終再生が 7 日以内なら `w × 0.25`。ユニット単位ではユニットの集計評価・集計最終再生を使う。
- **重み付きでない場合**：Fisher–Yates。
- **連続制限**（`max_same_kind_run = k`、k ≥ 1）：シャッフル後に先頭から走査し、同じ種類が k+1 個続いた位置 i を見つけたら、i より後ろで種類が異なる最初の要素 j と i を入れ替える。見つからなければ、i の要素を前のほうの「入れても k を超えない」いちばん前の位置へ移して走査し直す（ADR-85）。それもなければそこで終了（制約を満たせない場合は満たせる範囲まで）。ユニット単位では、ユニットの「代表種類」（メンバーで最も多い種類、同数なら video > audio > image）で判定する。決定的な処理なので乱数は使わない。

### 5.5 ユニット内シャッフル

`inner_shuffle` のユニットは、プレイリストのシャッフルがオフでも、ファイル単位でも、中だけシャッフルする（ADR-88）。ユニットごとのシードは `splitmix64(seed ^ fnv1a64(unit_key の正規化文字列))` で作る（正規化文字列は `u:<unit_id>` または `f:<folder_id>:<0|1>`）。こうすると、ユニットの並び順が変わっても各ユニットの中の並びは同じになる。

### 5.6 性能

1 万エントリ・展開後 5 万アイテムで、`resolve + build_queue` が 50ms 以内（Apple Silicon、リリースビルド）。

## 6. 再生

### 6.1 コントローラ

- フロントの `PlaybackController`（`src/features/player/engine/`）は Rust から受け取ったキュー（Slot 列）を順に再生するだけ。並び替えロジックは持たない。
- 要素は 3 つ：`<video>`、BGM 用の `<audio>` 2 つ（クロスフェード用）、画像レイヤー。
- 再生 URL は `kura://localhost/play/{hash}`（プロキシがあればプロキシ、なければ元ファイル）。
- 次のスロットの先読み：画像は次の 2 件を decode、動画・音楽は次の 1 件の `preload="metadata"`。

### 6.2 画像の間の BGM（`bgm_through_images`）

- 現在のスロットが画像で、直前に再生していた音楽がまだ終わっていなければ、その音楽を流し続ける。
- 音楽が途中で終わったら無音にする（設定「BGM をループ」がオンならその曲をループ）。
- 動画のスロットに入ったら BGM を 300ms でフェードアウトして一時停止する（動画は自分の音声を使う）。
- 次の音楽スロットに来たら、BGM をその曲に切り替える（300ms のクロスフェード）。
- 音楽スロットそのものは「音楽の再生時間ぶん」進む。画像スロットは表示時間ぶん進む。

### 6.3 操作

| 操作 | ファイル単位 | ユニット単位 |
|---|---|---|
| → / 次へ | 次のスロット | 次のスロット |
| ← / 前へ | 再生位置 3 秒以上なら先頭へ、未満なら前のスロット | 同左 |
| ⇧→ | 次のスロット | 次のユニットの先頭 |
| ⇧← | 前のスロット | 今のユニットの先頭（すでに先頭なら前のユニットの先頭） |
| [ / ] | 画像の表示時間 −1 秒 / +1 秒（このセッションだけ） | 同左 |
| S | シャッフル切り替え（今のアイテムを先頭にキューを作り直す） | 同左 |

### 6.4 再生済みの判定と記録

- 音楽・動画：再生時間の 50% 以上、または 4 分以上再生したら「再生済み」。
- 画像：表示時間を最後まで表示した、または 2 秒以上表示してから次へ進んだら「再生済み」。
- 再生済みになったら `playback_report` で `play_events` に記録し、アイテムの `play_count` と `last_played_at` を更新する。ユニットとして再生されたスロットなら、ユニットの `play_count` は「そのユニットの最初のスロットが再生済みになったとき」に 1 増やし、`last_played_at` は毎回更新する。

### 6.5 再開

プレイリストごとに `playlist_state`（シード、スロット番号、アイテム、再生位置）を保存する。次回の再生で「続きから」を選んだら、同じシードでキューを作り直してそこから再生する。エントリが変わっていてスロットのアイテムが違えば、同じアイテムの最初のスロットから、それも見つからなければ先頭から（ADR-86）。

## 7. UI の要点（デザインは `docs/design.md`）

- プレイリスト画面のタイトル横に **単位の切り替え**（セグメント「ファイル｜ユニット」）を置く。新規作成ダイアログにも同じ切り替えを置く。
- ユニット単位の一覧：ユニット行は 44px の表紙（奥に 2 枚重なった表現）、名前、「10 ファイル · 画像 · 1:20」、展開の ▸、並べ替えハンドル。単体の行には「単体」と小さく表示。
- ファイル単位の一覧：平らなリスト。unit / folder エントリから展開された行の前に、薄い見出し「鎌倉（フォルダ）から · 24 件」を出す。
- シアター：ユニット単位のときは上部に「ユニット 3 / 12 · 2 / 10」、キューのパネルはユニットごとに折りたたんで表示する。
- ライブラリのグリッド：設定「ユニットをまとめて表示」がオンなら、set ユニットは重なったタイル＋件数バッジで 1 枚として表示し、ダブルクリックで中身を開く。
