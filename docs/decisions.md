# 設計判断の記録（ADR）

新しい判断はこの表の下に追記します。覆すときは古い行を消さず「置き換え：ADR-xx」と書きます。

| ID | 判断 | 理由 | 検討した代案 |
|---|---|---|---|
| ADR-01 | v1 は macOS 専用（Apple Silicon、macOS 26 以降） | 利用者が Mac のみ。ネイティブ API（ImageIO・AVFoundation・APFS クローン）で性能と見た目を取れる | 最初からクロスプラットフォーム（工数が大きい） |
| ADR-02 | OS 依存は `kura-mac` に隔離し、`kura-core` は OS 非依存 | テストを Linux でも回せる。将来の Windows 対応の余地 | 全部 1 クレート |
| ADR-03 | Tauri 2 ＋ React / TypeScript | 軽量・高速。React は資料と実績が最も多く、Claude Code での実装が安定する | Svelte 5（さらに軽い）、Electron（重い）、SwiftUI（Rust の資産が使えない） |
| ADR-04 | UI ライブラリを使わず、トークン＋自作部品 | デザインの一貫性と軽さ | Radix などのヘッドレス部品（必要になれば部分的に検討） |
| ADR-05 | SQLite（rusqlite、WAL）、全文検索は FTS5 trigram | 単一ファイルで速い。trigram は日本語の部分一致に向く | Tantivy などの検索エンジン（v1 には過剰） |
| ADR-06 | 実ファイルは内容アドレス（BLAKE3 名）で保存 | 重複排除が自然にでき、名前の衝突がない | 元のファイル名で保存（衝突・改名の扱いが複雑） |
| ADR-07 | コピーは reflink（APFS クローン）を優先、だめなら通常コピー | 同一ボリュームでは瞬時で容量も増えない | ハードリンク（元ファイルの変更が波及する） |
| ADR-08 | サムネイル・メディア情報は Swift ヘルパー（ImageIO / AVFoundation）、扱えない形式は ffmpeg | 速く、HEIC・RAW などに強い | libvips（同梱が手間）、ffmpeg のみ（遅い） |
| ADR-09 | 再生は WKWebView ＋必要なときだけ再生用プロキシ。mpv は「外部プレイヤーで開く」の選択肢にとどめる | シアターなどのデザインをアプリ内で一貫させるため。Mac 専用なので VideoToolbox で変換が速い | mpv を主に使う（見た目が分断される）、libmpv 埋め込み（実装が重い） |
| ADR-10 | ダウンロードは yt-dlp / gallery-dl を外部プロセスとして呼び、同梱しない | サイトの変更に合わせた更新が頻繁なため、ユーザー環境（Homebrew）で更新する | 同梱（更新が追いつかない） |
| ADR-11 | キャプチャは chromiumoxide ＋インストール済み Chrome（ルール方式）、見たままは WKWebView のスナップショット | 要素単位・ページ全体の撮影が安定。ログイン状態をプロファイルで保持できる | Playwright（Node が必要） |
| ADR-12 | ガラス表現は CSS の `backdrop-filter` のみ。ウィンドウの透明化と macOS の private API は使わない | 設定が単純で、デザインの再現が確実。読みやすさ優先の方針とも合う | window-vibrancy の `apply_liquid_glass`（private API が必要。M9 で試験的に検討） |
| ADR-13 | ユニット（set / folder）をデータとして第一級に持つ | 「管理単位」でのプレイリスト作成・シャッフルの要件。ダウンロードの複数ページ作品などにも使える | フォルダだけで代用（ファイル群をまとめられない） |
| ADR-14 | プレイリストの単位（file / unit）は表示とキュー生成の違いとして持ち、切り替えは非破壊 | 切り替えで内容を失わない。「ファイルに固定」は明示操作に分ける | 単位ごとに別のプレイリスト種別にする（行き来できない） |
| ADR-15 | シャッフルは ChaCha8 のシード付き乱数のみ | 同じシードで同じ並びを、バージョンや OS が変わっても再現するため | `StdRng`（将来のバージョンで結果が変わりうる） |
| ADR-16 | 型付き IPC は tauri-specta | Rust の型から TS の型を自動生成し、食い違いを防ぐ | ts-rs（コマンドの型は手書きになる）。tauri-specta が使いにくければこちらに切り替えて記録する |
| ADR-17 | 一覧は「ID と縦横比を先に全件、詳細は見えている分だけ」 | 10 万件でも JS 側の負担を小さく保ちつつ、ジャスティファイ配置を事前に計算できる | ページング（スクロール位置の扱いが複雑） |
| ADR-18 | バンドル ID は `dev.kura.Kura`（M0） | `tauri.conf.json` に必須。ログ（`~/Library/Logs/dev.kura.Kura`）やアプリのデータの置き場所がこれで決まる | 正式なアプリ名が決まるまで保留（ビルドできない） |
| ADR-19 | 取り込みは「staging にコピー（クローン）→ コピーした側のハッシュ → files/ へ rename」の順（M1） | 取り込み中に元のファイルが書き換えられても、ファイル名（ハッシュ）と中身が必ず一致する | 先にハッシュを取ってからコピー（別ディスクの重複ファイルを無駄にコピーしないが、名前と中身がずれうる） |
| ADR-20 | 走査は walkdir（M1） | architecture にあった jwalk は開発が終わっている。walkdir は広く使われ、並び順を指定できる | jwalk（並列走査だが保守されていない） |
| ADR-21 | 取り込みのコピー・ハッシュ・配置は最大 6 並列（M1） | 2 万件（16KB）・16 コアの実測で、6 並列 3.6 秒、8 並列 4.5 秒、16 並列 11 秒。APFS のクローンと rename が取り合いになる。M9 で大きなファイル・HDD を含めて測り直す | CPU コア数（architecture の当初案）。HDD で 2 並列にする判定は未実装 |
| ADR-22 | kura-core の DB・ジョブは同期のスレッドで書き、tokio を使わない（M1） | DB の書き込みは専用スレッド、ジョブはジョブごとのスレッド、並列処理は rayon で足りる。Tauri とは進捗のコールバックだけでつなぐので、テストに非同期ランタイムがいらない | tokio のタスクで書く |
| ADR-23 | 重複の扱いは「スキップ（コピーはせず、フォルダ・タグ・ユニットへの追加だけ行う）」と「何もしない」の 2 択（M1） | architecture §6 の動作を既定にし、何も変えたくない場合も選べるようにする。スキップのとき、同じ中身がゴミ箱にあれば戻して重複と数える | 重複も複製する（内容アドレスなので不可） |
| ADR-24 | フォルダ構成の再現では、ドロップしたフォルダを取り込み先に対応させる。取り込み先がなければドロップしたフォルダ名でいちばん上に作る。フォルダ名のタグは、ドロップしたフォルダからファイルの親までの全階層（M1） | 取り込みシートのモックの例（旅行2026/鎌倉 → 写真/2026 旅行/鎌倉）に合わせる | 取り込み先の下にドロップしたフォルダごと作る／タグは直上のフォルダだけ |
| ADR-25 | ファイル名・フォルダ名・タグ名は NFC に正規化して保存する（M1） | macOS のファイル名は分解形（NFD）のことがあり、そのままでは入力した文字と一致せず検索で見つからない | そのまま保存 |
| ADR-26 | メディア情報（幅・高さ・長さ・撮影日時）の読み取りは M2。M1 で取り込んだアイテムは M2 の読み取りジョブで埋める。「ファイルの情報からタグ」も M2 で有効にし、撮影地は保留 | MediaBackend はロードマップ上 M2。撮影地を地名にするには逆ジオコーディング（通信）が必要で NFR-10 とぶつかる | M1 で probe まで実装する |
| ADR-27 | モックにない画面の形（M1）：初回起動は中央のガラスのカード（新しく作る／既存を開く、同期フォルダは警告）。ドロップ中は暗幕＋内側 16px の点線の枠。取り込みの進捗はグリッド下中央のガラスのカプセル（一時停止・中止、完了は数秒で消える） | design.md の部品と方針の範囲で作る。M5 でミニプレーヤーと並ぶ形に調整する | — |
| ADR-28 | kura-core に specta を入れず、フロントとやり取りする型は src-tauri の DTO に変換して出す（M1） | kura-core を Tauri から独立に保つ（architecture §2 の依存の範囲） | kura-core の型に specta を derive する |
| ADR-29 | 開発サーバーのポートは 1430（M0） | Tauri の既定の 1420 は他のプロジェクトとぶつかりやすい | 1420 |
| ADR-30 | 「ファイルの情報からタグ」は `アーティスト:`・`アルバム:` だけ付ける（M2） | 撮影日は `captured_at` 列にあり、M4 の検索で絞れるのでタグにすると重複する。撮影地は ADR-26 のとおり保留 | 撮影日（年・月）もタグにする |
| ADR-31 | サムネイルのジョブは同時に 1 つで、ジョブの中で CPU コア数の並列にする。未作成のものを 64 件ずつ取り出し、1 トランザクションで書く（M2） | アイテムごとにジョブを作ると 10 万件で `jobs` に 10 万行でき、進捗の表示も細切れになる。後続は `ensure_queued` で積むので重複しない | architecture の当初案（thumbnail の同時実行数 = CPU コア数） |
| ADR-32 | flac・ogg・opus・mkv・webm・avi は ffmpeg / ffprobe を先に試し、それ以外は macOS（ImageIO / AVFoundation）を先に試す（M2） | AVFoundation は FLAC のタグとジャケットを読めず、mkv・webm は開けない。macOS を先に試すと空の情報で成功してしまう | 常に macOS を先に試し、扱えないときだけ ffmpeg |
| ADR-33 | `items_query_ids` は tauri-specta を通さず、`tauri::ipc::Response` で生バイトを返す。型は `src/ipc/items.ts` で持つ（M2） | 型付きコマンドは JSON になり、10 万件の ID と縦横比が大きく遅くなる。生バイトなら ArrayBuffer で届き、10 万件で 606KB・18ms | ID を JSON の配列で返す |
| ADR-34 | ジャケットのない音楽は `thumb_state = 'failed'`（エラーなし）にし、グリッドでは音楽の絵を出す（M2） | 何度作り直しても結果は同じ。状態を増やすとマイグレーションが要る | 新しい状態 `none` を足す |
| ADR-35 | 日付見出しは追加日を端末の時差で区切り、「今日・昨日・10月8日（木）・2025年10月8日（水）」と書く。時差はフロントから `items_query_ids` に渡す（M2） | Rust 側でタイムゾーンのデータを持たずに済む。撮影日の見出しは M4 の並び替えと一緒に検討する | Rust で OS の時差を読む／撮影日で区切る |
| ADR-36 | M2 のツールバーは取り込み・インスペクタの開閉（⌘I）・サムネイルの大きさ（スライダーと ⌘+ / ⌘−、行の高さ 5 段階）だけ。選択はクリックで 1 件、←→ で移動、スペースでクイックルック。複数選択は M3（M2） | M2 で動く機能だけ出す。種類・評価などのチップは M4、並べ方の切り替えはジャスティファイのみ | モックのボタンを先にすべて置く |
| ADR-37 | Swift ヘルパーは C 文字列と整数だけで `extern "C"` で呼び、swift-rs はビルド時のリンクにだけ使う（M2） | swift-rs の型（`SRString` など）を使うと Swift 側もそのパッケージに依存する。C の型だけなら依存がなく、メモリの持ち主も明確（probe の JSON は `kura_free_string` で解放） | swift-rs の型で受け渡す |
| ADR-38 | 「最近の取り込み」は追加から 7 日以内（M3） | 検索の `追加:7日以内` と同じ範囲にして覚えやすくする | 最後の取り込みの分だけ／30 日以内 |
| ADR-39 | 「ランダム」は、開くたびに新しいシード（ChaCha8）で全件をランダムな順に並べる表示。見出しなし。ランダム再生は M5／M6（M3） | 再生の仕組みがまだないので、見て回る用途だけ先に入れる。シードは開いたときに決めるので、読み直しても並びは変わらない | 再生のマイルストーンまで出さない |
| ADR-40 | フォルダを開いたときの表示とサイドバーの件数は、子孫フォルダの分を含める（同じアイテムは 1 回）（M3） | 検索の `フォルダ:写真` が子孫を含むのと合わせる。「このフォルダから外す」（⌫）は子孫フォルダからも外す | そのフォルダに直接入っている分だけ |
| ADR-41 | サイドバーのスマートフォルダ（M4）・プレイリスト（M6）・取得（M7）の欄と、下の容量・設定（M9）は、その機能を入れるときに出す（M3） | ADR-36 と同じく、動く機能だけ出す | 欄だけ先に置く |
| ADR-42 | 複数選択では評価・タグ・フォルダ・メモを全件に適用し、タイトルは 1 件のときだけ変えられる。メモは内容が違えば「複数の値」と出し、入力したら全件を置き換える（M3） | 同じタイトルを何件にも付ける場面がない。メモは一括で付けたいことがある | タイトルも一括／メモは 1 件だけ |
| ADR-43 | 「ユニットをまとめて表示」はツールバーのボタンで切り替え、表示の設定として `localStorage` に置く（M3） | 設定画面は M9。見た目の設定なので localStorage でよい（CLAUDE.md） | DB の settings に置く |
