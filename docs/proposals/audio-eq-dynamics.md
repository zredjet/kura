## 1. ねらい

- FabFilter Pro-Q 4・Pro-C 3 にある実用的な機能の大半を、操作エンジンの約束（決定性・版・区間ごとに描く。editing.md §1）の上で作る。
- **スペクトルの上で効率よく編集できること**を中心に置く。アナライザは EQ・コンプに欠かせない部品で、音声エディタの常設の表示にもする。表現は豊かにしてよい。
- 見た目は写さない（design.md のトークンと部品で組む）。FabFilter の音（スタイルの調律・Character）の再現も目標にしない。
- 画面の言葉は日本語（design.md §5「英語の UI 用語は使わない」）：イコライザ・コンプレッサー・リミッター・圧縮量（ゲインリダクション）・チャンネル・セント。この文書では短く EQ・コンプ・GR とも書く。
- Kura ならではの強み：
  - あとから描くので、先読み・直線位相の遅れは位置をずらして補うだけで、出力は遅れない。
  - 全体が見える：圧縮量・ダイナミック EQ の動きを曲の全体に重ね、選んだ区間の平均のスペクトルを出せる。
  - 操作は一括加工のレシピ（M14）にそのまま載る（例：効果音 1,000 件に 低域カット＋コンプ＋−1 dBTP のリミッター）。
  - 版の契約で、同じ文書からいつでも同じ結果を作り直せる。

## 3. 決めること

### D1 状態を運ぶ操作の正と、状態の表

今の音声の核は「どの区間も単独で描けて、切り方を変えても同じ値」（editing.md §5.3・E18）で、「状態を運ぶフィルタは核にせず、解析の側で順に流す」と決めてある（§5.3・engine.md・`audio/mod.rs` の冒頭）。IIR の EQ・コンプは過去の全標本に依るので、そのままでは載らない。

**推奨**（承認済み）：

1. **正は先頭から順に流した値**（状態は f64、標本ごと）。保存・一括・解析・ダイジェストはこれだけを使う。
2. **状態の表は、操作が申告する内部用の解析にする**（normalize が `audio.loudness_gating` を申告するのと同じ形。§11.2）。表は格子 G ごとの状態（フィルタの状態・先読みの列・係数を替える位置・有限でない標本があったか）の正規の形のバイナリで、見積もりを持ち、流して解く（`Analysis::stream`）。核は表を受け取り、区間の頭より前の最も近い境目から流す。流すのを止めて再開しても値は同じなので、区間の切り方によらずビット一致する（E18）。
   - **G は表の正規の形の一部として凍結する定数**（`STATE_GRID`。`AUDIO_CHUNK` とは別の名前で、値は同じ 65,536 でもよい。§8.2(2) の「速さのためだけの値」ではない）。変えるなら解析と操作の版を上げて旧版を legacy に残す。
   - 表は `kura-peaks` に続く 2 つ目の決めたバイナリなので、読み手（`from_canonical`）・ファズの対象・状態の NaN のビット列の揃え方を段 1 に入れる。
   - 解析の引数は**状態に効く引数だけ**にする（出力の利得・mix などを入れると、それを動かすだけで長い音声の表を流し直す）。
3. 申告した解析なので、**操作と組で凍結**する（結果を変えるなら両方の版を上げる。§8.4）。E26 の対の表・`FAKES`・`kernel_registry` に載せる。
4. **届く範囲の型を 3 つ足す**（`render/region.rs` の `Reach`。どれも保守的で、0 と長さで切る）：

   | 型 | 逆（核が読む区間） | 前（変わった範囲の写し） | 使う所 |
   |---|---|---|---|
   | `Prefix { after }` | [0, b + after) | [a − after, n) | 状態を運ぶ操作の `reach`（after は先読み。リミッターは先読み ＋ K ＋ V。§4.2） |
   | `Aligned { grid, before, after }` | [⌊(a − before)/grid⌋·grid, b + after) | [a − after, n)（保守的） | 状態の表を使う核の `audio_reach`（grid = G。EQ・コンプは before = 0、リミッターは before = K ＋ V） |
   | `Window { before, after, align }` | [⌊a/align⌋·align − before, ⌈b/align⌉·align + after) | [⌊(a − after)/align⌋·align, ⌈(b + before)/align⌉·align) | 出力のブロックを絶対位置 0 に揃える重なり保存の形（直線位相。align は FFT のブロック B） |

   時間の写しは Identity（遅れはずらして補うので、時刻は変わらない）。実行器も `audio_reach_is_sound` も頼みをチャンク（C）に揃えてから写すので、align・grid が C を割り切る値だけでは式の穴が見えない。段 1 の性質テストに、C を割り切らない・C より大きい値（3·4,096、2C）を足す。B（直線位相の FFT のブロック）・K（リミッターの直す段のブロック）・V（その重なり）・G（状態の表の格子）は、それぞれ操作の版に凍結する別の値で、`AUDIO_CHUNK` の倍数であることに頼らない（§8.2(2)）。
5. **保存・一括も表を先に流して解く**：流して書く保存は窓ごとに範囲の描画（前の値なし）で描くので（`stream_audio`）、窓をまたいで状態を運べない。表の流し解き 1 回のあと、今の書き出し（Ogg Vorbis は後ろ向きと前向きの 2 回）を行う。
6. **入れ子の鎖**：EQ → コンプ → リミッターのように状態を運ぶノードが続くと、流し解きが入れ子になり、k 段で O(k²) 回流す。
   - 段 1 で「鎖を前向きの 1 回の流しでまとめて解く口」（各ノードが流しながら状態を運び、表を控え、出力を次のノードへ渡す。値は同じ）を測り、入れるかを決める。M18 の鎖の速さ（§6）はこれで決まる。
   - 裏の仕事は、入力の 1 回（表と前の STFT）と出力の 1 回（波形の段・計り・後の STFT）に束ねる。1 回にするには「解析を解きながら出力も出す」新しい道が要る。
7. **凍結する細かい規則**：
   - 有限でない標本（NaN・∞）は 0 としてフィルタに入れ、その位置はそのまま出す。表に「有限でない標本があったか」を持たせ、核を作るとき（`audio_kernel`）に警告する（核は警告を返さないので、描いた区間によらない形にする。E18）。FFT は 1 つの NaN でブロック全体（と隣の重なり）を壊すので、直線位相・STFT（表示）・リミッターの直す段の計りも、有限でない標本は 0 として FFT・補間に入れる。直線位相の出力は、その位置の元の値をそのまま出す。
   - 何も変えない設定（0 dB のバンド・オフのバンド・空の列）は飛ばし、残らなければ核を `Identity` にする（§5.3 の約束）。
   - サブノーマル：アプリは Apple Silicon だけなので、効くのは Linux のテストの時間だけ。段 1 で x86_64 の Linux（手元か手で起こす CI）でテストの時間を測り、遅ければ「小さい状態を 0 にする」規則を v1 に入れる。
8. **チャンネルをまとめて描く口**：M/S のバンドやステレオのリンクでは、出力の各チャンネルが両方の入力に依る。核はチャンネルを 1 つずつ描くので、そのままでは同じ計算を 2 回する。全チャンネルを一度に描く口を核に足すか、2 倍の手間を受け入れるかを段 1 で決める。リンク・M/S では表の流しも 1 スレッドになる。
9. **核の続きの流し**：核はチャンネルごとに「直前に描いた終わりの位置と状態」を覚え、続きの頼みは続きから流す（値は同じ。`Send + Sync` なので錠か仕事ごとの複製にし、作業領域として `work_bytes` に数える）。これがないと、E18 の 1・7 フレームずつの描画で毎回 G から流し直し、受け入れテストが現実的な時間で回らない。核が内に覚えを持つので、§5.3・engine.md の「`render` は出力の区間を描く純粋な関数」の文言を、段 1 で「値に効かない覚え（続きの流し）は持ってよい。並列の仕事の間で共有しないか、錠で守る」に改める。

見積もり（推測）：2 次の段は、多くの段を交互に回して 1 段・1 標本あたり約 1 ns（1 段だけなら再帰の依存で 2〜3 ns）。8 段の EQ の表は 5 分のステレオで約 0.1 秒、60 分で約 1.4 秒。最悪の 24 バンド × 96 dB/oct は 192 段で、60 分では 1 チャンネル 30 秒を超えるので、段の数に上限を置く。コンプは対数の検出で標本ごとに `math` の log10・pow を呼ぶので、IIR より重い（1 回 10〜20 ns）。

**代案**：
- 決まった格子ごとに助走をつけて描くのを正にする：格子の継ぎ目の小さな段差が保存される。
- 線形の EQ だけ「ブロックごとに零状態で流し、境の状態を行列の冪で運んで流し直す」形を正にする：時間の向きにも並べられるが、順に流した値とは一致しない（それを正にする決定になる）。コンプには使えない。
- IIR をやめて全部 FIR にする：最小位相の長い FIR は重く、コンプは FIR にできない。

### D2 聴きながら動かしたときの反応と、描けない間の表示・試聴

再生の道は今のまま（Rust が描いた PCM を Web Audio で鳴らし、手のあと 60 ms 先から 10 ms の交差フェードで替える。替えは 150 ms に 1 回まで。ADR-177）。

**推奨**（承認済み。描けない間の道は見直しで足した）：

- **点・曲線・スペクトルの見た目は常にすぐ**：点は手元で動き、曲線は描かずに求める口（`edit_eq_curve`。係数とデジタルの周波数応答を返す。描画を待たない）で追う。後のスペクトルはドラッグ中「前のスペクトル＋曲線」で描く（D3）。
- **音は M17 では正だけで作る**：
  - 手間（段の数 × フレームの数）が小さい音声は、手ごとに正で描き、NFR-11（エンジンの中 25 ms）を目指す。表の流しはチャンネルの数までしか並ばないので、境の目安は 8 段で約 20 秒のステレオ（推測。段 2 で測って決める）。今の 32 MiB の境（ADR-176 (2)）とは別に、手間で決める。
  - 手間が大きい音声は NFR-11 の対象外にする（レート変換の ADR-187、正規化の手前を動かしたときと同じ扱い）。**状態を運ぶノードより上流の手**（切り詰め・フェード・音量など）も、表を入力の全体に流し直すので同じく対象外になる。requirements.md の NFR-11 の注と ADR-176 (2) を改訂する。
- **描けない間の表示と試聴**（見直しで足した決めごと）：今のフロントは、公開された表示の有効な区間に入っているチャンクしか取らない（`playback.ts` の `covered(view.valid, …)`）。表示の頼みは描きかけを止める（`Latest`）ので、長い音声で点を動かし続けると、新しい表示が出ないまま先読み（3 秒）が尽きて無音になる。そこで：
  - セッションは**最後に公開した rev の計画（文書と状態の表）を握り続け**、新しい手の流し解きが終わるまで、表示と試聴の先読みの頼みはその計画で描いて公開する（rev は古いまま。再生は途切れない）。
  - 流し解きは最新の手だけを裏で進め（新しい手が来たら止めて最新へ）、終わったら新しい rev を公開し、今の交差フェードで替える。
  - 正規化の手前を動かすときの今の振る舞いも段 3 で確かめ、同じ穴があれば同じ道に載せる。
  - 要る仕組み（どれも今の公開の口にない）：
    - **申告した解析を区切りで進め、キャッシュに入れるエンジンの口**（`Engine::presolve_step` のようなもの）。ノードの入力のポートを流して止めて続きから再開でき、解けた結果は実行器と同じ鍵（`analysis_fingerprint`。§12.2）でノードのキャッシュに入れる。結果は `run` とビット一致（E35 と同じ照らし方）。今の流し解きは描画の中の非公開の手続き（`render/audio.rs` の `presolve`）でしか起きない。
    - **裏の仕事の区切り**：セッションの描画は錠で順に行う（ADR-176・§12.12）ので、流し解きを錠の中で 1 回で行うと、その間は古い計画の表示・試聴も描けない。長い音声の計り（§12.12 の A16）と同じく、`work` の区切り（40 ms）で少しずつ進める。
    - **応えの約束**：表示の rev と頭の rev が違う応えを返してよく、フロントはそれを当てる（`edit_step`・`edit_view` の結果、`applyView`、保存していない変更の判定は頭の rev で見る）。波形の段と計りは表示の `samplesId` で引く。
    - 握り続ける古い計画の表とノードの値は、エディタの取り置きの `CacheLease` の extra に数える。
  - 代案：流し解きを止めずに終わってから最新へ進む（音の更新がさらに遅れる）／無音を受け入れて「描いています…」を出す。
- **長い音声の近似の道は、触ってから決める**：段 2 で短い音声の反応を測り、段 5 で長い音声を触る。足りなければ「助走の近似の道」を後の段か次のマイルストーンで入れる（下の「近似の道を入れるときに作るもの」）。それでも足りなければ、ネイティブ（CoreAudio）の実時間の道を別のマイルストーンとして検討する（今は入れない）。
- **後の候補：状態の表の差分の流し解き**：上流の手で変わった位置の前の境までの表は使い回し、後ろだけ解き直す（`Prefix` の前の写しで後ろだけが変わるので成り立つ。末尾のフェードアウトの手などが速くなる）。

**近似の道を入れるときに作るもの**（今の実行器にはない。M13 段 1 並みの大きさ）：

- 計画の印（音声の近似の段）と指紋。今のプレビューの段（§12.7）は画像のためのもので、音声は段 0 に落ちる。
- 解析を申告しない近似の核の口。助走はチャンク k ごとに kC − W から流す（頼んだ区間によらず値が決まる）。W は時定数から決めて上限を置く（推測：20 Hz・Q 18 のベルは −100 dB まで 3〜4 秒、release 2.5 秒のコンプは数十秒）。コンプの初めの状態（最初の検出値から始める等）も決める。
- 由来 `Approx`（キャッシュに入れない）。下流に解析を申告するノード（normalize など）があるときの落ち方。
- 同じ rev のまま近似から正に替わったことをフロントに知らせる世代（`samplesId` を変えるか表示の世代を足す）と、そのときの交差フェード。
- 近似の値から波形の段・計り・スペクトルを作るか（作るなら印を付けて公開し、正で作り直す）。エディタの受け入れの約束 A6〜A8 の文言を改める。

**代案**：Web Audio の BiquadFilterNode・DynamicsCompressorNode で鳴らす。聞いた音と保存する音が別物になる。

### D3 スペクトルの源

**推奨**（承認済み。帯の定義・置き方は見直しで詰めた）：**Rust の STFT を 1 つの源にする**。

- **置き方**：式（窓・帯・量子化）は kura-engine の純粋な関数と式の識別子（`kura-spec/1`）で持ち、タイルはセッションの部品で作る（波形の段の `PeaksPatch` と同じ置き方）。`Analysis` には登録しない（値 → 結果の形に合わず、E1・E24〜26・E35 やゴールデンが掛かるため。ライブラリに残す要が出たら、そのとき解析にする）。表示だけなので版をまたいだ値の約束はしないが、エンジンの規則（`math`・`par_blocks`）には従う。
- **窓**：大きさは 2 の冪（44.1・48 kHz で 4,096、88.2・96 kHz で 8,192、のようにレートから丸める）、Hann、hop は 1/4。フレームは**中心の位置**で定義する（中心 = k·hop、頭の外は 0）。
- **低域**：4,096 点は 48 kHz で 1 ビン 11.7 Hz で、20〜100 Hz に約 7 本しかない。200 Hz より下は 16,384 点の窓にする多重解像度にし（2 つの窓は中心で揃える）、直流を除いてから窓をかける。
- **帯**：対数（1/48 オクターブ、20 Hz〜ナイキスト。48 kHz で約 491 帯）。帯の値は**帯に入るビンの平均のパワー（密度）**、ビンのない帯は隣のビンから補う。傾きの補正（例：4.5 dB/oct）は密度に対してかける。量子化は dB（例：0.5 dB 刻みの u8）。
- **チャンネル**：L・R・M・S・和（和は**チャンネルのパワーの和**）。
- **区間の平均**：dB ではなくパワーの領域で取る。長い区間（⌘A で 60 分など）の平均は Rust の裏の仕事（波形の段・計りと同じ `work` の区切り。進みと中止つき）で作り、計っている間は前の平均を薄く出す。
- **量と作り方**：60 分では 1 つの選び方で約 83 MB になるので、全体は作らない。区間のタイルを頼まれたら作り、LRU で持つ（エディタの取り置きの予算で数える）。窓はチャンクをまたぐので、部分の作り直しでは変わった区間の前後に（窓 − hop）を足す。
- **配信**：`kura://localhost/edit/{session}/…/spec/…`。`/peaks` と同じく、ポートの指紋か表示の世代で引いて immutable にする。どのノードの入力・出力かを指せる（Pro-Q の「前・後」は、そのノードの入力と出力）。内部のポートを窓ごとに流す口は `stream_port`（`pub(super)`）があるので、公開の口にする。
- **値の出どころ**：正の値だけから作る（近似の道を入れたら、近似の値の STFT は作らないか、印を付けて正で作り直す）。
- **1 つの源から出すもの**：再生中のアナライザ、止まっているときのカーソルの位置・選んだ区間の平均と最大、前と後、スペクトログラム。後の候補の EQ マッチ・共振の候補も同じ源を使う（EQ マッチは文書に引数を書くだけにし、STFT を申告しない）。
- **ドラッグ中の後のスペクトル**：「前のスペクトル＋曲線」で即座に描き、描けた後のスペクトルが届いたら替える（EQ は線形で時間で変わらないので良い近似になる。表示のチャンネルとバンドのチャンネルが合うときだけ。コンプには使わない）。

**代案**：WebKit の AnalyserNode。鳴っている音そのもので遅れがないが、前のスペクトルには元も同時に鳴らす必要があり、止まっているとき・選んだ区間・スペクトログラム・EQ マッチに使えず、源が 2 つになる。

### D4 スペクトルの面の置き場（ADR-177 の改訂）

**推奨**（承認済み。道具・キー・上部の行は見直しで詰めた）：

1. **切り替え**：舞台の表示を **波形｜スペクトル｜スペクトログラム** で切り替えるセグメントを上部の中央に置く。キーは ⌘1・⌘2・⌘3（ライブラリの表示形式と同じ形。音声エディタだけの割り当てで、画像エディタの ⌘1 とは別）。メニューはページより先にキーを取る（ADR-76）ので、音声エディタの間の表示のメニューに「波形 ⌘1・スペクトル ⌘2・スペクトログラム ⌘3」を足す。上部の中央は ADR-177 で「同じ読み上げの名前のボタンを 2 か所に置かない」ために空けてあり、聞き比べをそこに置く案は「道具の場所が画像と違う」として退けている。表示の切り替えは道具ではなく、ほかの場所に同じボタンもないので、ADR-177 の改訂としてここに置く。
2. **自動で替える条件**：EQ を足したときと、波形を見ていて EQ を選んだときだけスペクトルに替える。スペクトログラムを見ているときは替えない。
3. **面が出すノード**：選んだ EQ、なければ最後の EQ、なければ出力のアナライザだけ（曲線なし）。
4. **道具**：スペクトル・スペクトログラムのときに T・F・R（切り詰め・フェード・ループ）を押したら、波形に戻して道具を替える。選択は細い波形の帯とスペクトログラムの段でも使え、ループの旗はスペクトログラムの目盛りでも動かせる。カプセルの下の段は、スペクトルのときはスペクトルの欄（選んだバンドの読み・［一時的に外して聞く］・一言）。
5. **上部の名前と情報の行**：切り替えの左端までで省略する。「未保存」は名前の横の印に移し、情報の行は末尾から省略する。2 つのエディタで出し方を分けないため、画像エディタの上部（「64 × 64 · PNG · 未保存」）も同じ印に揃える（design.md §3.1 の画像エディタの改訂）。窓 1280〜1512pt で上部の重なり・省略を測る（段 5 の完了に入れる）。

**代案**：
- 下のカプセルの上の段に置く：ADR-177 の幅の測り直しが要り、カプセルが混む。
- 右パネルや下の引き出しに小さく出す：面が狭く「スペクトルの上で効率よく」に届かない。

### D5 EQ の引数の形

**推奨**（承認済み。型の一覧と推論は見直しで詰めた）：**1 つの操作 `audio.eq` にバンドの列**（最大 24。段の数の上限も置く）。新しい引数の型 `EqBands`。曲線が 1 枚で見え、1 回で流せる。

v1 で凍結するバンドの型と、使う引数：

| 型 | 周波数 | 利得 | Q | 傾き |
|---|---|---|---|---|
| ベル | ○ | ○ | ○ | — |
| ローシェルフ・ハイシェルフ | ○ | ○ | ○（肩の形） | — |
| ローカット・ハイカット | ○ | — | — | ○（6〜96 dB/oct） |
| ノッチ | ○ | — | ○ | — |
| バンドパス | ○ | — | ○ | — |
| チルト | ○（中心） | ○ | — | — |

どのバンドもチャンネル（すべて｜L｜R｜M｜S。「すべて」はチャンネルの数によらずどのチャンネルにも当てる）とオン／オフを持つ。型を足すときは、D8 と同じく操作の版を上げて旧版からは何もしない `migrate` にする（版の解決・「新しすぎる版」の判定・レシピの `requires` は（操作, 版）で見るため）。

入力の形で意味が決まらない組み合わせは、推論での扱いを凍結する（一括で形の違う素材に当たるため）：

- 周波数がナイキスト以上：ローカット・バンドパスは断る（帯の外を削るので、全部を削る指定になり意図が分からない）。ハイカット・ノッチは外して警告（外しても意図と同じ）。ベル・シェルフ・チルトは周波数を 0.49 × レートに止めて警告。
- モノラル：S のバンドは外して警告し、L・R・M はそのチャンネルに当てる。
- 3 チャンネル以上：L・R は 1・2 チャンネル目、M・S のバンドは外して警告。

**代案**：バンドごとのノード。操作の並びが長くなり、合成の曲線を組み立てにくい。

### D6 最小位相のフィルタの式と形

**推奨**（承認済み）：

- **式**：ベル・LP・HP・バンドパスは Vicanek "Matched Second Order Digital Filters"（2016）のアナログに合わせた 2 次。シェルフ・チルトはこの論文の範囲外なので、ナイキストの利得を指定する設計（Orfanidis）などを段 2 で選ぶ。カットは Butterworth の 2 次の段を重ねて 6〜96 dB/oct（奇数次は 1 次を足す）。式は `math` だけで書く。極端な Q・ナイキストに近い周波数・根の中が負になる設定の扱いも凍結の範囲に入れる。
- **形**：M18 のダイナミック EQ（係数を時間で替える）を見込んで、DF-I か TPT の SVF から段 2 で選ぶ。状態の持ち方・縦続の順（列の順）も凍結し、バンドの間は f64 のまま運んで最後に 1 回だけ f32 にする。ここが合っていれば、M18 で v2 を足したときに v1 の実装を消せる（動きのないバンドで v1 とビット単位で同じになるとき）。
- **照らす相手**：実装の正しさは「係数から求めたデジタルの応答」と正弦の掃引で ±0.05 dB。アナログの原型との差は別の上限（例：0.9 × ナイキストまで ±0.5 dB）で書く。

**代案**：RBJ の Audio EQ Cookbook。簡単だが、ナイキストの近くでベルが細くなり、シェルフが曲がる。

### D7 直線位相

**推奨**（承認済み。届く範囲は見直しで直した）：M17 で `audio.eq` の `phase`（最小｜直線）として入れる。

- 目標の振幅から FIR を作る（周波数の標本化＋窓）。長さ L は最も低い周波数と帯域（Q・傾き）から決め、上限を置く。20 Hz・Q 10 のノッチは 48 kHz で数万タップになり、上限で切ると低域の形が目標からずれるので、曲線は目標ではなく実際の FIR の応答を返す。
- L は奇数（I 型）にし、遅れ D = (L − 1)/2 を整数でずらして消す。入力の外は 0、長さは変えない。
- FFT の畳み込みは**重なり保存**で、出力のブロック（長さ B）を絶対位置 0 に結び、FFT と B を版に凍結する。出力のブロック [jB, (j+1)B) の値は、丸めまで含めると入力の窓 [jB − D, (j+1)B + D) の全体に依るので、`reach`・`audio_reach` は `Window { before: D, after: D, align: B }`（D1-4）。**状態がないので表は要らない**。
- 性能（推測）：6 万タップ級で 1 標本・1 チャンネルあたり数十 ns、5 分のステレオで 1 パス 1 秒以上。**NFR-11 の対象外**にし（動かしている間は古い音。D2 の描けない間の道に載る）、前のリンギングは表示で知らせる。
- M18 のダイナミック EQ との組み合わせは断る。

**代案**：後のマイルストーンに回す。

### D8 コンプのスタイル（M18）

**推奨**（承認済み）：v1 は 3 つ。公開された検出器の型（Giannoulis・Massberg・Reiss（2012））を自分の式で凍結する。

| スタイル | 検出 | 先読み |
|---|---|---|
| クリーン | 前向き。対数の領域の滑らかな attack・release | 使える |
| パンチ | 帰還型（出力から検出） | 使えない（表示の条件 `visible` で欄を出さず、値を持っていても使わない、と凍結） |
| オプト | 前向き。入力に応じて伸びる release | 使える |

- スタイルを足すときも、操作の版を上げて旧版からは何もしない `migrate` にする。
- 凍結の前に M18 段 1 の実測で決める選び肢：利得の計算を絶対位置の決まった格子で間引く（例：16 標本ごとに計算して補間）、log・pow をしきい値・ニーの外では省く。
- 静的な曲線の照らし方：ピークの検出はしきい値をピークのレベルと、RMS の検出は RMS のレベルと比べる（正弦の RMS はピークより 3.01 dB 低い）。

**代案**：1 つだけにする（表現の幅が狭い）。FabFilter と同じ数にする（調律の手間に見合わない）。

### D9 試聴だけの重ね（ソロ・一時的に外して聞く・音量を合わせて聞く）

**推奨**（承認済み。鍵・入口・名前は見直しで詰めた）：文書に入れず、取り消しの外で、**音だけに効く**「重ね」をセッションに持つ（表示・波形・アナライザは文書の値のまま）。

- **鍵**：表示の `samplesId`（文書の出力の指紋。今のまま）と、試聴の識別子 `auditionId`（試聴の計画の出力の指紋。重ねがなければ `samplesId` と同じ）を分ける。PCM の URL・`kura` チャンクのデコーダ（今の `kura-edit/1:{samplesId}`）・フロントの照らし（`playback.ts` の `view.samplesId`）は `auditionId` を使う。`samplesId` はラウドネスの結果を覚える鍵で、計りかけを捨てる判定にも使うので、重ねで変えると計りが「計っています…」に戻ってしまう。
- **計画**：セッションは試聴用の計画をもう 1 つ持つ（ドラッグの仮の値と同時に使える）。キャッシュと予算の分け方は段 6 で決める。長い音声では D2 の描けない間の道に載る。表示の計画と試聴の計画の両方に流し解きが要るときは、試聴の計画を先に進める（聞こえる音を先に替える）。握る古い計画は表示と試聴の 2 つまで。
- **ソロ**：右パネルの［ソロで聞く］（押すたびに切り替え、`aria-pressed`）と、スペクトルの面で選んだバンドに対して Q キーを押している間。⌥ はシークと同じ「細かく動かす」に使うので使わない（ADR-230）。鳴らす帯は、ベル・ノッチ・バンドパスは中心と Q、シェルフ・カットは境の周波数を中心に 1 オクターブ。チルトはソロなし。キーは段 5 で design.md §6 の表と照らして決める。
- **一時的に外して聞く**：選んだノードを外した音を鳴らす（EQ 1 つの前後を聞く。今の B は「元｜編集後」だけ）。右パネルの操作の行の有効のスイッチ（文書に入り、取り消せる）と分けるため、名前は「一時的に外して聞く」とし、一言で「文書は変えません」と出す。
- **音量を合わせて聞く**：聞き比べの隣のアイコンのボタン（押してある間合わせる）。比べる両方（元と編集後、外した音と外さない音）のラウドネスを計り、**大きいほうを下げる**（上げない。0 dBFS を超えないため）。長い音声で計り直している間は前の利得のまま。操作の「ラウドネスをそろえる」（`audio.normalize`）と名前を分ける。今の仕様は「音量はそろえない」（design.md §3.1、ADR-177 (3)）なので、その改訂になる。

**代案**：`audio.eq` に自動の利得を入れる。出力のラウドネスを計る申告が要り、引数を動かすたびに全体を計り直す。

## 4. 作るもの

### 4.1 M17 スペクトルと EQ

**エンジン**：D1 の正の道、`audio.eq` v1（D5〜D7）、自作の FFT（実数、基数 2 と 4、f64、`math` だけ。Vorbis・AAC の FFT はコーデックの値と一致させるためのものなので共有しない）、STFT の式と内部のポートを流す公開の口（D3）、`edit_eq_curve`（曲線の式は Rust だけに置き、TypeScript は返った点を描くだけ）。

**スペクトルの面**：

- 横は対数の周波数（20 Hz〜ナイキスト）、縦は左にイコライザの ±dB（±6／12／30 の切り替え）、右にスペクトルの dBFS。
- 後のスペクトル（塗り）・前（実線）・最大の保持（点線）。線の形で分ける（design.md §7「色だけで状態を伝えない」）。落ちる速さと傾きの補正は表示だけの設定。
- 合成の曲線（柿色の太い線）と、選んだバンドの曲線・効く帯の塗り。ほかのバンドの曲線は、ポインタを載せたバンドだけ出す（細い線が重なりすぎないため）。
- バンドの点：ドラッグで周波数と利得（⌥ で 1/10 の速さ。ADR-230 と同じ）、選んだ点の左右の小さな印のドラッグで Q。ホイールで Q を変えるのは、点を選んでいてポインタがその点の上にあるときだけ（トラックパッドのスクロールで点の上を通っただけで手にならないため）。空きのダブルクリックでベルを足し、点のダブルクリックで消す。右クリックで型・チャンネル・オン／オフ。
- **山をつかむ**：ポインタの近くのスペクトルの山を印で示し、そこからドラッグするとその周波数にベルができる（低域は長い窓の値で探す）。
- ホバーで周波数・音名とセント（A4 = 440 Hz）・スペクトルの dB・曲線の dB。
- **キー**（スペクトルの面にフォーカスがあるとき）：← → で選んだバンドの周波数（1/12 オクターブ）、↑ ↓ で利得（0.5 dB。利得のない型は、カットは傾き、ノッチ・バンドパスは Q）、⇧ で大きく、⌥ で細かく（ADR-230 に揃える）、⌫ で選んだバンドを消す（面の外では今どおり「選んだ操作を消す」）、[ ] で前・次のバンド（音声エディタでは空き）。Tab は今どおりフォーカスを次の部品へ動かす。
- **読み上げとキーの道**：面は `role="group"`・`aria-label`（「スペクトルの面」）にし、選んだバンドの読み（カプセルの下の段と同じ文）を `aria-describedby` で添える。面の点は飾り（`aria-hidden`）にし、右パネルのバンドの表の行（`<button>`）と欄（`<input>`＋`<label>`）を、キーと読み上げの道にする。
- **右パネル**：イコライザの引数（位相（最小｜直線）・出力の利得・バンドの表・［＋ バンドを足す］・選んだバンドの欄・［ソロで聞く］［バンドを消す］）。値の欄は右パネルだけに置く（同じ欄を 2 か所に置かない）。下に固定のラウドネス・出力の形式（design.md §3.1）は残し、引数の欄はその上でスクロールする。バンドの表は 8 行を超えたら表の中だけスクロールする。
- **下のカプセルの下の段**：選んだバンドの読み（文字だけ）・［一時的に外して聞く］・使い方の一言。カプセルの幅は増やさない。
- **アナライザの同期**：再生中は Web Audio の時刻 → 出力のフレーム → 時間の写し（`Plan::time_chain`・`TimeMap::back`。下流に trim・resample があれば EQ のノードのフレームとずれる）→ STFT のフレーム。止まっていれば選んだ区間の平均（なければカーソルの位置）。

**スペクトログラム**：時間×周波数の面のタイル。チャンネルの段・目盛り・全体図は波形と同じ。表示の設定（見るポート・チャンネル・下限の dB・色の凡例）は面の右上。**色の表はメディアの表示として扱い、アクセントの色を含めない**（無彩色の明るさの段。再生位置・ループ・選択の柿色と白が埋もれないため）。色の正本はトークンで Rust は読めないので、Rust が強さを配ってフロントが塗るか、フロントが渡す色の表で Rust が塗るかは段 8 で決める。

### 4.2 M18 ダイナミクス

- **包絡線の部品**：ピーク・RMS の検出、attack・release・hold、入力に応じた release、ステレオのリンク（0〜100%）、M/S、サイドチェーンのフィルタ（EQ のバンドの部品を使う）。状態の表（D1）に載せる。
- **`audio.compress` v1**：threshold・ratio（1:1〜∞）・knee（0〜72 dB）・range・attack（0.005〜250 ms）・release（10〜2,500 ms と自動）・hold・lookahead（0〜20 ms。出力は遅れない）・サイドチェーンのフィルタ・リンク・M/S・mix（並列）・出力の利得・スタイル（D8）。
- **`audio.limit` v1**：トゥルーピークを見るリミッター。今のトゥルーピークの補間（12 タップ × 4 相）は、利得が補間の中で変わると負の係数のせいで上限を超えうるので、検出だけでは約束できない。凍結する式に「確かめて直す」段を入れる：
  - 絶対位置に結んだブロック（凍結）ごとに、前後の重なり（凍結）を付けて、同じ関数で出力を計り、超えた所の補間の範囲の利得を下げて繰り返す。回数に上限を置き、届かなければそのブロックをまとめて下げる。書くのはブロックの中だけ（区間の切り方によらない。E18）。
  - 直す段は主の利得の計算の状態に戻さない（凍結）。直す段のブロックの長さを K、重なり（回数の上限 × 補間の幅を含む）を V とすると（直線位相の B とは別の値）、届く範囲は 1 つずつの申告で `reach = Prefix { after: 先読み + K + V }`、`audio_reach = Aligned { grid: G, before: K + V, after: 先読み + K + V }`（D1-4）。
  - 約束の範囲は操作の出力の f32 の値（ディザ・非可逆の書き出し・下流の操作は含まない。f32 に丸める分の余裕を取り、終わりの後ろの流し切りの標本も数える）。
- **ダイナミック EQ**：`audio.eq` v2 で、バンドごとに threshold・range（±）・attack・release・ratio を足す。補間は係数ではなく引数（dB）の領域で行い、絶対位置に結んだ格子ごとに係数を作り直す（2 次の係数を線形に補間すると、途中の形が意図した形にならない）。v1 の文書は動きのないバンドへ `migrate` する（D6 の形が合えば v1 の実装を消せる。合わなければ legacy に残す）。直線位相との組み合わせは断る。
- **圧縮量の値の出どころ**：操作の内部の値を外へ出す口が `Op` にない（出力 ÷ 入力は lookahead・makeup・mix が入るので圧縮量にならない）。表示だけの系列を出す口を足す。
- **画面**：
  - 入出力の伝達の曲線（threshold・ratio・knee をドラッグ）。
  - **圧縮量を波形の全体に重ねる**：コンプレッサー・リミッターを選んでいるときだけ出す。段の上から下へ、波形の後ろに描く（大きな音のピークを隠さない）。最も深い所の印は、見えている範囲のもの。
  - 再生位置の入力・出力・圧縮量のメーター（ADR-177 はメーターを退けているので、その改訂になる）。
  - サイドチェーンのフィルタは［スペクトルで直す］でスペクトルの面に移って直す。
  - ダイナミック EQ は点の周りに range の輪と、いま動いている利得を出す。

## 9. 危うい所

- 状態の表を作る時間と鎖の入れ子が見積もりより大きい → 段 1 で最初に測る。段の数の上限を置く。鎖をまとめて解く口を検討する。
- 長い音声で、動かしている間の音が古いままなのが使いにくい → 段 3 で途切れない道を作り、段 5 で触って近似の道を入れるかを決める（D2）。
- 手ごとに正で描ける境が短い（約 20 秒）→ 効果音には足りるが、曲では NFR-11 の対象外が増える。段 2 で測って利用者と決める。
- WebKit でアナライザとスペクトログラムを 60 fps で描けるか → スペクトログラムはタイル、canvas は線と点だけにする。
- 引数の多い操作の凍結 → v1 で出す型・範囲を絞り、足すときは版を上げて `migrate` を書く。M18 を見込んで M17 でフィルタの形を決める。
- ADR-177 の改訂が 3 つ（上部の中央・音量を合わせて聞く・メーター）と ADR-176 (2) の改訂が重なる → 段 5 と M18 段 5 で design.md の正本を書くときにまとめて見直す。
