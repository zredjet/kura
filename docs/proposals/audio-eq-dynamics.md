# 音声の EQ・ダイナミクス・スペクトルの案（M17・M18）

> 状態：**案**（2026-11-24。新しいエージェントの見直しを受けて直した版）。正本ではありません。§3 の決めごとが承認されたら、roadmap.md・editing.md・design.md・requirements.md・decisions.md（ADR）・`.claude/rules/engine.md` へ移し、このファイルは消します。要件・ADR の番号は入れるときに決めます（NFR-18 は M15 で使用済み、ADR は feat/seek-bar の ADR-230 の次から）。

## 1. ねらい

- FabFilter Pro-Q 4・Pro-C 3 にある実用的な機能の大半を、操作エンジンの約束（決定性・版・区間ごとに描く。editing.md §1）の上で作る。
- **スペクトルの上で効率よく編集できること**を中心に置く。アナライザは EQ・コンプに欠かせない部品で、音声エディタの常設の表示にもする。表現は豊かにしてよい。
- 見た目は写さない（design.md のトークンと部品で組む）。FabFilter の音（スタイルの調律・Character）の再現も目標にしない。
- Kura ならではの強み：
  - あとから描くので、先読み・直線位相の遅れは位置をずらして補うだけで、出力は遅れない。
  - 全体が見える：ゲインリダクション・ダイナミック EQ の動きを曲の全体に重ね、選んだ区間の平均のスペクトルを出せる。
  - 操作は一括加工のレシピ（M14）にそのまま載る（例：効果音 1,000 件に 低域カット＋コンプ＋−1 dBTP のリミッタ）。
  - 版の契約で、同じ文書からいつでも同じ結果を作り直せる。

## 2. 分け方

| マイルストーン | 中身 | 大きさの目安 |
|---|---|---|
| M17 スペクトルと EQ | 状態を運ぶ操作の正の道、`audio.eq`（最小位相・直線位相）、FFT と STFT、アナライザとスペクトルの面、スペクトログラム、試聴だけの重ね（ソロ・バイパス・音量をそろえる） | M13 より大きい |
| M18 ダイナミクス | 包絡線の部品、`audio.compress`・`audio.limit`、ダイナミック EQ（`audio.eq` v2）、ゲインリダクションの表示 | M13 くらい |
| 後の候補 | 長い音声のドラッグ中の近似の道（D2 で測ってから）、スペクトログラムの上の編集（時間×周波数の範囲を選んで減らす・直す）、EQ マッチ、共振の候補の提示、スペクトルダイナミクス、Character（倍音）、外のサイドチェーン | 未定 |

M18 は M17 の土台（状態の表・フィルタの形・STFT・スペクトルの面）を使うので、この順にする。

## 3. 決めること（承認がほしい点）

### D1 状態を運ぶ操作の正と、状態の表

今の音声の核は「どの区間も単独で描けて、切り方を変えても同じ値」（editing.md §5.3・E18）で、「状態を運ぶフィルタは核にせず、解析の側で順に流す」と決めてある（§5.3・engine.md・`audio/mod.rs` の冒頭）。IIR の EQ・コンプは過去の全標本に依るので、そのままでは載らない。

**推奨**：

1. **正は先頭から順に流した値**（状態は f64、標本ごと）。保存・一括・解析・ダイジェストはこれだけを使う。
2. **状態の表は、操作が申告する内部用の解析にする**（normalize が `audio.loudness_gating` を申告するのと同じ形。§11.2）。表は境目（格子 G。速さのためだけの値）ごとの状態の正規の形のバイナリで、見積もりを持ち、流して解く（`Analysis::stream`）。核は表を受け取り、区間の頭より前の最も近い境目から流す。流すのを止めて再開しても値は同じなので、区間の切り方によらずビット一致する（E18）。控えるのは状態のすべて（フィルタの状態・先読みの列・係数を替える位置）。
3. 申告した解析なので、**操作と組で凍結**する（結果を変えるなら両方の版を上げる。§8.4）。E26 の対の表・`FAKES`・`kernel_registry` に載せる。
4. **届く範囲の型を 2 つ足す**（`render/region.rs` の `Reach`）：`Prefix { after }`（前へは [a, n) に広がり、逆には [0, b + after)）と `Window { before, after }`（逆には [a − before, b + after)。直線位相・先読み・トゥルーピークの補間）。操作の `reach` は `Prefix`、`audio_reach` は [⌊a/G⌋·G, b + 先読み)。時間の写しは Identity（遅れはずらして補う）。
5. **保存・一括も表を先に流して解く**：流して書く保存は窓ごとに範囲の描画（前の値なし）で描くので（`stream_audio`）、窓をまたいで状態を運べない。表の流し解き 1 回のあと、今の書き出し（Ogg Vorbis は後ろ向きと前向きの 2 回）を行う。
6. **入れ子の鎖**：EQ → comp → limit のように状態を運ぶノードが続くと、流し解きが入れ子になり、k 段で O(k²) 回流す。見積もりは鎖の形で出し、裏の仕事は表・波形の段・計り・STFT を 1 回の流しに束ねる。
7. **凍結する細かい規則**：有限でない標本（NaN・∞）は 0 としてフィルタに入れ、その位置はそのまま出して警告する（案）。何も変えない設定（0 dB のバンド・オフのバンド・空の列）は飛ばし、残らなければ核を `Identity` にする（§5.3 の約束）。サブノーマルは Apple Silicon では遅くならない見込みだが、CI の x86 で測る（遅ければ「小さい状態を 0 にする」規則を v1 に入れる）。
8. **チャンネルをまとめて描く口**：M/S のバンドやステレオのリンクでは、出力の各チャンネルが両方の入力に依る。核はチャンネルを 1 つずつ描くので、そのままでは同じ計算を 2 回する。全チャンネルを一度に描く口を核に足すか、2 倍の手間を受け入れるかを段 1 で決める。

見積もり（推測）：2 次の段は、多くの段を交互に回して 1 段・1 標本あたり約 1 ns（1 段だけなら再帰の依存で 2〜3 ns）。8 段の EQ は 5 分のステレオで約 0.1 秒、60 分で約 1.4 秒。最悪の 24 バンド × 96 dB/oct は 192 段で、60 分では 1 チャンネル 30 秒を超えるので、段の数に上限を置く。コンプは対数の検出で標本ごとに `math` の log10・pow を呼ぶので、IIR より重い（1 回 10〜20 ns の推測）。

**代案**：
- 決まった格子ごとに助走をつけて描くのを正にする：格子の継ぎ目の小さな段差が保存される。
- 線形の EQ だけ「ブロックごとに零状態で流し、境の状態を行列の冪で運んで流し直す」形を正にする：時間の向きにも並べられるが、順に流した値とは一致しない（それを正にする決定になる）。コンプには使えない。
- IIR をやめて全部 FIR にする：最小位相の長い FIR は重く、コンプは FIR にできない。

### D2 聴きながら動かしたときの反応

再生の道は今のまま（Rust が描いた PCM を Web Audio で鳴らし、手のあと 60 ms 先から 10 ms の交差フェードで替える。替えは 150 ms に 1 回まで。ADR-177）。

**推奨**：

- **点・曲線・スペクトルの見た目は常にすぐ**：点は手元で動き、曲線は描かずに求める口（`edit_eq_curve`。係数とデジタルの周波数応答を返す。描画を待たない）で追う。後のスペクトルはドラッグ中「前のスペクトル＋曲線」で描く（D3）。
- **音は、M17 では正だけで作る**。手間（段の数 × フレームの数）が小さい音声は手ごとに正で描き、NFR-11 を目指す。大きい音声は NFR-11 の対象外にして、動かしている間は古い音、描けたら替える（レート変換の ADR-187、正規化の手前を動かしたとき（requirements.md の NFR-11 の注）と同じ扱い）。境は 32 MiB ではなく手間で決め、ドラッグ中に描く区間（再生の先読みのチャンクだけ等）も決める。
- **長い音声の近似の道は、触ってから決める**：段 2 で短い音声の反応を測り、段 4 で長い音声を触る。足りなければ「助走の近似の道」を後の段か次のマイルストーンで入れる（下の「近似の道を入れるときに作るもの」）。
- それでも足りなければ、ネイティブ（CoreAudio）の実時間の道を別のマイルストーンとして検討する（今は入れない）。

**近似の道を入れるときに作るもの**（今の実行器にはない。M13 段 1 並みの大きさ）：

- 計画の印（音声の近似の段）と指紋。今のプレビューの段（§12.7）は画像のためのもので、音声は段 0 に落ちる。
- 解析を申告しない近似の核の口。助走はチャンク k ごとに kC − W から流す（頼んだ区間によらず値が決まる）。W は時定数から決めて上限を置く（推測：20 Hz・Q 18 のベルは −100 dB まで 3〜4 秒、release 2.5 秒のコンプは数十秒）。コンプの初めの状態（最初の検出値から始める等）も決める。
- 由来 `Approx`（キャッシュに入れない）。下流に解析を申告するノード（normalize など）があるときの落ち方。
- 同じ rev のまま近似から正に替わったことをフロントに知らせる世代（`samplesId` を変えるか表示の世代を足す）と、そのときの交差フェード。
- 近似の値から波形の段・計り・スペクトルを作るか（作るなら印を付けて公開し、正で作り直す）。エディタの受け入れの約束 A6〜A8 の文言を改める。

**代案**：
- 初めから近似の道を入れる：M17 が大きくなり、いちばん危うい所を測る前に作ることになる。
- Web Audio の BiquadFilterNode・DynamicsCompressorNode で鳴らす：聞いた音と保存する音が別物になる。

### D3 スペクトルの源

**推奨**：**Rust の STFT を 1 つの源にする**。

- **窓**：大きさは 2 の冪（44.1・48 kHz で 4,096、88.2・96 kHz で 8,192、のようにレートから丸める）、Hann、hop は 1/4。格子は絶対位置（フレーム 0 から hop ごと）。
- **低域**：4,096 点は 48 kHz で 1 ビン 11.7 Hz で、20〜100 Hz に約 7 本しかない。低域だけ長い窓（例：200 Hz より下は 16,384 点）にする多重解像度にし、直流を除いてから窓をかける。
- **帯**：対数（1/48 オクターブ、20 Hz〜ナイキスト。48 kHz で約 491 帯）。帯の値はパワーの和、量子化は dB（例：0.5 dB 刻みの u8）。選んだ区間の平均は dB ではなくパワーの領域で取る。
- **チャンネル**：L・R・M・S・和を選べる。
- **量と作り方**：60 分では 1 つの選び方で約 83 MB になるので、全体は作らない。区間のタイルを頼まれたら作り、LRU で持つ（エディタの取り置きの予算で数える）。窓はチャンクをまたぐので、部分の作り直しでは変わった区間の前後に（窓 − hop）を足す。
- **配信**：`kura://localhost/edit/{session}/…/spec/…`。`/peaks` と同じく、ポートの指紋か表示の世代で引いて immutable にする。どのノードの入力・出力かを指せる（Pro-Q の「前・後」は、そのノードの入力と出力）。内部のポートを窓ごとに流す口が今はない（`stream_audio` は出力だけ）ので足す。
- **値の出どころ**：正の値だけから作る（近似の道を入れたら、近似の値の STFT は作らないか、印を付けて正で作り直す）。表示だけの解析で、操作は申告しない（申告すると量子化ごと凍結される）。
- **1 つの源から出すもの**：再生中のアナライザ、止まっているときのカーソルの位置・選んだ区間の平均と最大、前と後、スペクトログラム。後の候補の EQ マッチ・共振の候補も同じ源を使う（EQ マッチは文書に引数を書くだけにする）。
- **ドラッグ中の後のスペクトル**：「前のスペクトル＋曲線」で即座に描き、描けた後のスペクトルが届いたら替える（EQ は線形で時間で変わらないので良い近似になる。表示のチャンネルとバンドのチャンネルが合うときだけ。コンプには使わない）。

**代案**：WebKit の AnalyserNode。鳴っている音そのもので遅れがないが、前のスペクトルには元も同時に鳴らす必要があり、止まっているとき・選んだ区間・スペクトログラム・EQ マッチに使えず、源が 2 つになる。

### D4 スペクトルの面の置き場（ADR-177 の改訂）

**推奨**：舞台の表示を **波形｜スペクトル｜スペクトログラム** で切り替えるセグメントを、上部の中央に置く。EQ のノードを選ぶ・足すとスペクトルに替わる。スペクトルのときも上に細い波形の帯（全体図・見ている範囲・再生位置・選択）を残し、時間の操作はそこで行う。

上部の中央は ADR-177 で「同じ読み上げの名前のボタンを 2 か所に置かない」ために空けてあり、聞き比べをそこに置く案は「道具の場所が画像と違う」として退けている。表示の切り替えは道具ではなく、ほかの場所に同じボタンもないので、ADR-177 の改訂としてここに置く（画像エディタの上部の中央は道具のカプセルで、置き方の違いは残る）。

**代案**：
- 下のカプセルの上の段に置く：ADR-177 の幅の測り直しが要り、カプセルが混む。
- 右パネルや下の引き出しに小さく出す：面が狭く「スペクトルの上で効率よく」に届かない。

### D5 EQ の引数の形

**推奨**：**1 つの操作 `audio.eq` にバンドの列**（最大 24。段の数の上限も置く）。新しい引数の型 `EqBands`（型・周波数・利得・Q・傾き・チャンネル（ステレオ｜L｜R｜M｜S）・オン／オフ）。曲線が 1 枚で見え、1 回で流せる。

入力の形で意味が決まらない組み合わせは、推論での扱いを凍結する（一括で形の違う素材に当たるため）。案：ナイキスト以上のバンドは外して警告、モノラルでは S のバンドを外して警告し L・R・M はそのチャンネルに当てる、3 チャンネル以上では L・R は 1・2 チャンネル目、M・S のバンドは外して警告。

**代案**：バンドごとのノード。操作の並びが長くなり、合成の曲線を組み立てにくい。

### D6 最小位相のフィルタの式と形

**推奨**：

- **式**：ベル・LP・HP・バンドパスは Vicanek "Matched Second Order Digital Filters"（2016）のアナログに合わせた 2 次。シェルフ・チルトはこの論文の範囲外なので、ナイキストの利得を指定する設計（Orfanidis）などを段 2 で選ぶ。カットは Butterworth の 2 次の段を重ねて 6〜96 dB/oct（奇数次は 1 次を足す）。式は `math` だけで書く。極端な Q・ナイキストに近い・超える周波数・根の中が負になる設定の扱いも凍結の範囲に入れる。
- **形**：M18 のダイナミック EQ（係数を時間で替える）を見込んで、DF-I か TPT の SVF から段 2 で選ぶ。状態の持ち方・縦続の順（列の順）も凍結し、バンドの間は f64 のまま運んで最後に 1 回だけ f32 にする。ここが合っていれば、M18 で v2 を足したときに v1 の実装を消せる（動きのないバンドで v1 とビット単位で同じになるとき）。
- **照らす相手**：実装の正しさは「係数から求めたデジタルの応答」と正弦の掃引で ±0.05 dB。アナログの原型との差は別の上限（例：0.9 × ナイキストまで ±0.5 dB）で書く。

**代案**：RBJ の Audio EQ Cookbook。簡単だが、ナイキストの近くでベルが細くなり、シェルフが曲がる。

### D7 直線位相

**推奨**：M17 で `audio.eq` の `phase`（最小｜直線）として入れる。

- 目標の振幅から FIR を作る（周波数の標本化＋窓）。長さは最も低い周波数と帯域（Q・傾き）から決め、上限を置く。20 Hz・Q 10 のノッチは 48 kHz で数万タップになり、上限で切ると低域の形が目標からずれるので、曲線は目標ではなく実際の FIR の応答を返す。
- 長さは奇数（I 型）にし、遅れを整数でずらして消す。入力の外は 0、長さは変えない。
- FFT の畳み込みのブロックの格子は絶対位置 0 に結び、FFT とブロックの大きさを版に凍結する（E18）。**状態がないので今の核の約束に載る**（届く範囲は `Window`）。
- 性能（推測）：6 万タップ級で 1 標本・1 チャンネルあたり数十 ns、5 分のステレオで 1 パス 1 秒以上。**NFR-11 の対象外**にし（動かしている間は古い音）、前のリンギングは表示で知らせる。

**代案**：後のマイルストーンに回す。

### D8 コンプのスタイル（M18）

**推奨**：v1 は 3 つ（クリーン・パンチ・オプト）。公開された検出器の型（Giannoulis・Massberg・Reiss（2012）の対数の領域の滑らかな attack・release、帰還型、入力に応じて伸びる release）を自分の式で凍結する。

- スタイルを足すときも、操作の版を上げて旧版からは何もしない `migrate` にする（版の解決・「新しすぎる版」の判定・レシピの `requires` は（操作, 版）で見るので、版を上げずに値を足すと古い Kura が誤って断る・誤って通す）。
- 帰還型は出力から検出するので、先読みと組み合わない。帰還型のスタイルでは先読みを無効にする（案）。

**代案**：1 つだけにする（表現の幅が狭い）。FabFilter と同じ数にする（調律の手間に見合わない）。

### D9 試聴だけの重ね（バンドのソロ・ノードのバイパス・音量をそろえる）

**推奨**：文書に入れず、取り消しの外で、試聴にだけ効く「重ね」をセッションに持つ。ドラッグの仮の値と同時に使えるようにする（今のセッションの仮の値は 1 つだけなので、別に持つ）。

- **バンドのソロ**：点を押している間、そのバンドが効く帯だけを鳴らす（ベル・ノッチは中心と Q のバンドパス、シェルフ・カットは境の周波数の前後の帯。段 4 で決める）。
- **ノードのバイパス**：選んだノードを外した音を鳴らす（EQ 1 つの前後を聞く。今の B は「元｜編集後」だけ）。
- **音量をそろえる**：聞き比べに「音量をそろえる」のスイッチを足し、鳴らすときだけ利得をかける（Pro-Q の Auto Gain の代わり）。元のラウドネスも計る（今は出力だけ）。長い音声で計り直している間は前の利得のまま。今の仕様は「音量はそろえない」（design.md §3.1、ADR-177 (3)）なので、その改訂になる。

**代案**：`audio.eq` に自動の利得を入れる。出力のラウドネスを計る申告が要り、引数を動かすたびに全体を計り直す。

## 4. 作るもの

### 4.1 M17 スペクトルと EQ

**エンジン**：D1 の正の道、`audio.eq` v1（D5〜D7）、自作の FFT（実数、基数 2 と 4、f64、`math` だけ。Vorbis・AAC の FFT はコーデックの値と一致させるためのものなので共有しない）、STFT と内部のポートを流す口（D3）、`edit_eq_curve`（曲線の式は Rust だけに置き、TypeScript は返った点を描くだけ）。

**スペクトルの面**：

- 横は対数の周波数（20 Hz〜ナイキスト）、縦は左に EQ の ±dB（±6／12／30 の切り替え）、右にスペクトルの dBFS。
- 後のスペクトル（塗り）・前（線）・最大の保持（細い線）。落ちる速さと傾きの補正（例：4.5 dB/oct。帯の値はパワーの和）は表示だけの設定。
- 合成の曲線（太い線）と各バンドの曲線（細い線。選んだバンドは帯を塗る）。
- バンドの点：ドラッグで周波数と利得、ホイールで Q（カットは傾き）、⇧ で細かく。空きのダブルクリックで足し、点のダブルクリックで消す。右クリックで型・チャンネル・オン／オフ。
- **山をつかむ**：ポインタの近くのスペクトルの山を印で示し、そこからドラッグするとその周波数に点ができる（低域は多重解像度の窓の値で探す）。
- ホバーで周波数・音名（A4 = 440 Hz）・スペクトルの dB・曲線の dB。
- 下のカプセルの欄：選んだバンドの型・周波数・利得・Q・傾き・チャンネル・オン／オフと、全体の出力の利得・位相（最小｜直線）。欄が増えるので、ADR-177 のカプセルの幅を測り直す。
- **アナライザの同期**：再生中は Web Audio の時刻 → 出力のフレーム → 時間の写し（`Plan::time_chain`・`TimeMap::back`。下流に trim・resample があれば EQ のノードのフレームとずれる）→ STFT のフレーム。止まっていれば選んだ区間の平均（なければカーソルの位置）。

**スペクトログラム**：時間×周波数の面のタイル。Rust は `tokens.css` を読めず明暗の切り替えにも追いつけないので、色の表はトークンから作る（Rust は強さを配ってフロントが塗るか、フロントが渡す色の表で Rust が塗るかは段 6 で決める）。波形の面と同じズーム・パン・選択。

### 4.2 M18 ダイナミクス

- **包絡線の部品**：ピーク・RMS の検出、attack・release・hold、入力に応じた release、ステレオのリンク（0〜100%）、M/S、サイドチェーンのフィルタ（EQ のバンドの部品を使う）。状態の表（D1）に載せる。
- **`audio.compress` v1**：threshold・ratio（1:1〜∞）・knee（0〜72 dB）・range・attack（0.005〜250 ms）・release（10〜2,500 ms と自動）・hold・lookahead（0〜20 ms。出力は遅れない）・サイドチェーンのフィルタ・リンク・M/S・mix（並列）・出力の利得・スタイル（D8）。
- **`audio.limit` v1**：トゥルーピークを見るリミッタ。今のトゥルーピークの補間（12 タップ × 4 相）は利得が補間の中で変わると負の係数のせいで上限を超えうるので、検出だけでは約束できない。凍結する式に「確かめて直す」段を入れる（同じ関数で出力を計り、超えた所の補間の範囲の利得を下げて繰り返す。回数に上限を置き、届かなければ区間をまとめて下げる）。約束の範囲は操作の出力の f32 の値（ディザ・非可逆の書き出し・下流の操作は含まない。f32 に丸める分の余裕を取り、終わりの後ろの流し切りの標本も数える）。
- **ダイナミック EQ**：`audio.eq` v2 で、バンドごとに threshold・range（±）・attack・release・ratio を足す。補間は係数ではなく引数（dB）の領域で行い、絶対位置に結んだ格子ごとに係数を作り直す（2 次の係数を線形に補間すると、途中の形が意図した形にならない）。v1 の文書は動きのないバンドへ `migrate` する（D6 の形が合えば v1 の実装を消せる。合わなければ legacy に残す）。直線位相との組み合わせは断る（案）。
- **ゲインリダクションの値の出どころ**：操作の内部の値を外へ出す口が `Op` にない（出力 ÷ 入力は lookahead・makeup・mix が入るので GR にならない）。表示だけの系列を出す口を足す。
- **画面**：入出力の伝達の曲線（threshold・ratio・knee をドラッグ）、**ゲインリダクションを波形の全体に重ねる**、再生位置の入力・出力・GR のメーター（ADR-177 はメーターを退けているので、その改訂になる）、サイドチェーンのフィルタはスペクトルの面で直す、ダイナミック EQ は点の周りに range の輪と、いま動いている利得。

## 7. 対象外（M17・M18）

- AU・VST のプラグインのホスト（決定性と版の契約を守れない）

## 9. 危うい所

- 状態の表を作る時間と鎖の入れ子が見積もりより大きい → 段 1 で最初に測る。段の数の上限を置く。
- 長い音声で、動かしている間の音が古いままなのが使いにくい → 段 4 で触って、近似の道を入れるかを決める（D2）。
- WebKit でアナライザとスペクトログラムを 60 fps で描けるか → スペクトログラムはタイル、canvas は線と点だけにする。
- 引数の多い操作の凍結 → v1 で出す型・範囲を絞り、足すときは版を上げて `migrate` を書く。M18 を見込んで M17 でフィルタの形を決める。
- ADR-177 の改訂が 3 つ（上部の中央・音量をそろえる・メーター）重なる → 段 4 と M18 段 5 で design.md の正本を書くときにまとめて見直す。
