# ロードマップ

マイルストーンは上から順に進めます。1 マイルストーン＝Claude Code の 1〜3 セッションが目安です。
各マイルストーンの「依頼文」をそのまま Claude Code に貼れば始められます。完了条件をすべて満たしたら、このファイルのチェックを付けてコミットします。

共通の進め方：

1. 依頼文を貼る → Claude Code が関連 docs を読み、計画を出す（プランモード推奨）
2. 計画を確認して承認 → 実装
3. `/verify` がすべて通る → 完了条件を 1 つずつ確認した結果を報告してもらう
4. 自分で `pnpm tauri dev` を起動して触る → 気になる点を伝えて直す
5. コミット

- [ ] 可逆の圧縮（inflate・deflate・LZW）を自作し、PNG・GIF の読み書きと aseprite・PSD の展開を替える
- [ ] キャプチャの DevTools の WebSocket と、FLAC の MD5 を自作に替える

**段**（2026-11-22 の計画。ADR-216。各段は実装 → /verify → 検証のワークフロー → 直し → コミット。どの段も、外す依存をdev 依存の照合の相手に残し、フィクスチャ・コーパス・差分のファズで一致を確かめてから差し替える）：
- [x] 段 1 FLAC の読み取りと MD5：自作の FLAC のデコーダ（STREAMINFO・SEEKTABLE・VORBIS_COMMENT・PICTURE、CONSTANT・VERBATIM・FIXED・LPC、Rice の 2 種、左右の相関 3 種、フレームの CRC-8・CRC-16、可変のブロック）。値は仕様で 1 つに決まるので識別子は `flac-symphonia-dec/1` のまま。MD5 は `codec/md5.rs`（RFC 1321 のテストベクタと、他のツールで作ったフィクスチャの STREAMINFO の MD5 で照らす）にし、書き出しの STREAMINFO もこれで書いて md-5 を外す。結果（2026-11-22）：`codec/flac_read.rs`・`codec/md5.rs`。受け付ける範囲と値の細部を symphonia 0.6.1 に合わせた（頭が `fLaC` でない・LPC のずらしが負なら `Unsupported`、STREAMINFO とフレームの頭の照合（番号は 2 つ前と比べる）、Vorbis コメントからタグにする規則、CRC-16 は合わなければ次の頭の直前で照らす、総フレーム数が不明なら切れた最後のフレームを捨てる、i32 の折り返し）。違うのは、あとにフレームが続く壊れたフレームを断る・総フレーム数があれば末尾の余分なデータを読み飛ばす・32 ビットのステレオの 33 ビットの差のチャンネルを正しく読む、の 3 つ（docs/editing.md §9.6）。照合のテストは、フィクスチャ 14・自作の書き出し 5・仕様の枝を乱数で通した正しい FLAC 3,000（CRC-16 の前の余分なバイトを含む）・それらを壊した約 8,000 で、symphonia が読めたものは同じ値（流して読む道も同じ標本）をデバッグと release で確かめた。コーデックのゴールデン（`flac-symphonia-dec@1`・`flac-kura-enc@1` の読み直し）はそのまま通る。読み手は PICTURE などの箱を持たなくなり、15 MiB の画像 3 つの FLAC の解析の山は 46.5 MiB から 1.8 MiB に（`held::flac` を合わせた）。速さは 5 分のステレオ 16 ビットで symphonia 0.173 秒・自作 0.189 秒（MD5 込み）。独立した見直し（エージェント）の指摘 4 つ（33 ビット・切れた最後のフレーム・CRC-16 の前の余分なバイト・走査の中止）を直した。md-5 と symphonia-bundle-flac は本番の依存から外れた（symphonia-bundle-flac は照合の dev 依存）
- [x] 段 2 Ogg の読み口と Vorbis の読み取り：Ogg のページ（CRC・ページをまたぐパケット・グラニュール・途中の切れ）とVorbis（識別・コメント・setup の codebook・floor 0/1・residue 0/1/2・mapping・mode、逆 MDCT・窓・重ね合わせ）。超越関数は `math` だけ。識別子は新しく `ogg-vorbis-kura-dec/1`、旧版 `ogg-vorbis-symphonia-dec/3` は `legacy` の読み手に移す（段 10 まで）。照合は lewton・ffmpeg（フィクスチャ）と自作のエンコーダの出力（`ogg-vorbis-kura-enc@1.jsonl`に、新しい読み手で読み直した行を新しい名前で足す）。Opus・FLAC の Ogg は形式の表どおり次の段へ回す。結果（2026-11-22。ADR-217・ADR-218）：Ogg の読み口は `codec/ogg_read.rs`（壊れたページは `Decode`、連結は `Unsupported`）、Vorbis は `codec/vorbis/dec/`（libvorbis 1.3.7 の読み取りを書き出しと同じ 12 か条で移した）。照合の正は C とのビット一致で、照合用の C に `oracle_dec` を足し、Vorbis のフィクスチャと自作の書き出しの 160 本（8 レート × 1・2・3・6・8 チャンネル × 品質 −1・0・5・10 × 4 種の音）で PCM がビット単位で一致する。独立の相手とは、フィクスチャの参照（lewton・ffmpeg の読み取り。`tests/fixtures.rs`）と長さがちょうど同じで値が許容差の内、前の symphonia（`/3`）とはフィクスチャで長さ・タグが同じで値の差 1e-4 未満。`ogg-vorbis-kura-enc@1.jsonl` に新しい読み手で読み直した行（`-kdec1`）を 35 行足し、デコーダのゴールデン `ogg-vorbis-kura-dec@1.jsonl` を作った。前の `ogg-vorbis-symphonia-dec/3` は旧版の読み手（`legacy_decoders`）。codebook の表は使う項目のぶんだけ作り（前の symphonia は全項目）、量を確保の前に予算で断る（ordered の codebook で数 KB の setup が数 GB を確保させる形を塞いだ）。読み手が持つ量の見積もり（`held::ogg`）を自作の読み手の歩き方と表の式に合わせ（`stream_held` に ordered の大きな codebook のケースを足した）、長さを数える道は復号の表を作らない。独立した見直し（エージェント）の指摘 5 つ（見積もりが識別ヘッダの長さ・頭のグラニュールで少なくなる、residue 0 の dim 0 で 0 で割る、グラニュールの位置の足し算のあふれ、`decodemap` が分割の数の 2 乗の時間、復号の表の確保が `try_reserve_exact` でない）を直した。速さは 5 分のステレオで symphonia 0.176 秒・自作 0.270 秒（最初は 0.378 秒。値を変えない形で、最初の表の幅・ビットの読み・CRC・桁の求め方・内側のループの借り方を直した）・同じ旗で組んだ C の libvorbis 0.32 秒。x86_64 での照合はしていない（Rust の側は `math` と `as` の飽和で環境によらない書き方。CI の Linux がゴールデンを照らす）
- [ ] 段 3 MP4 の読み口と ALAC：箱（ftyp・moov・trak・mdia・minf・stbl の stsd・stts・stsc・stsz・stz2・stco・co64、edts の elst、udta・meta の ilst、iTunSMPB）を上限つきで読み、`held_bytes` を数え直す。ALAC（整数）は`m4a-alac-symphonia-dec/1` のまま
- [ ] 段 4 AAC-LC：ADTS と MP4 の esds（AudioSpecificConfig）、SCE・CPE・LFE・DSE・PCE・FIL、ハフマン、逆量子化、スケールファクター、M/S・intensity、PNS、TNS、サイン・KBD の窓、逆 MDCT。SBR・PS は見つけて断る（HE-AAC は今どおり AudioToolbox へ）。表は新しいクレート `aac-tables`（symphonia-codec-aac から元の MPL-2.0 のまま写す。vorbis-tables と同じ形）。識別子は新しく `m4a-aac-kura-dec/1`・`aac-adts-kura-dec/1`、旧版は段 2 と同じ扱い。照合は ffmpeg・AudioToolbox（フィクスチャ）
- [ ] 段 5 旧版の Vorbis・AAC をアンカーへ移す：旧版の読み手で読んだ版の入力のうちアンカーのないものに、旧版の読み手で1 度だけアンカーを作るジョブ（読み直して記録の値のダイジェストと照らす。ライブラリを開いたときに積む。中止・再開できる）。旧識別子が記録されているほかの所（解析の事実・サムネイル・波形の指紋など）を洗い出し、読み直しで済むものとアンカーが要るものを分ける
- [ ] 段 6 inflate と PNG・aseprite・PSD の読み取り：CRC-32・Adler-32・inflate（stored・固定・動的ハフマン、上限つきの出力、流して展開、中止）、PNG の IDAT（フィルタ 5 種・Adam7・ビット深度 1〜16）。値は同じなので `png-rs-dec/1`・`/2` のまま（アンカーの中身の読み手も同じ）。aseprite・PSD の zlib の展開もこれにし、直接の miniz_oxide を外す。速さは今の png（fdeflate）と比べ、NFR-14 を満たす
- [ ] 段 7 deflate と PNG・APNG の書き出し：fast・balanced・high の 3 段を自分の式で凍結（一致の探し方・遅延一致・ブロックの切り方・ハフマンの作り方・フィルタの選び方）、APNG の acTL・fcTL・fdAT。識別子は `png-kura-enc/1`（旧`png-rs-enc/1` は残さない。§8.4）。balanced の大きさは今の png の 5% 増しまで（コーパスで測って記録）。直接の png を外す（resvg 経由では残る）
- [ ] 段 8 GIF の読み書き：読み口（論理画面・色表・GCE・NETSCAPE2.0 の繰り返し・インターレース・ブロックの継ぎ）とLZW の読み書き（表が満ちたときの clear を自分の規則で凍結）。読みは `gif-rs-dec/1` のまま、書きは `gif-kura-enc/1`。gif・weezl を外す
- [ ] 段 9 DevTools の WebSocket：`capture/ws.rs`（クライアントの握手（Sec-WebSocket-Accept を SHA-1 で照らす）、マスク（鍵は種つきの ChaCha8。種は `/dev/urandom`）、テキスト・分割・ping・pong・close、今の tungstenite の既定と同じフレーム 16 MiB・メッセージ 64 MiB の上限）と SHA-1（RFC 3174 のテストベクタ）。tungstenite は dev 依存に移し、テストの偽のサーバー兼照合の相手にする。本番から tungstenite と、ほかに使う所のない 10 クレート（data-encoding・httparse・rand 0.10・chacha20・sha1・digest 0.11・block-buffer・crypto-common・hybrid-array・const-oid）が消える（段 1 の md-5 と合わせて 12）
- [ ] 段 10 symphonia を外す：段 5 のジョブを利用者のライブラリで回し終えてから、symphonia の 7 クレート・third_party の写し 4 つ・`[patch.crates-io]`（ワークスペースと fuzz）・旧版の Vorbis・AAC の読み手を外す。旧識別子の版はアンカーから作り直す（アンカーがなければ `DecoderGone`）
- [ ] 段 11 計測と締め：依存の数・ビルドの時間・リリースのバイナリの大きさの前後、NFR-14・NFR-15・60 分の音声の保存・`mem_smoke`・`bench edit`、長いファズ（cargo-fuzz）、第三者のライセンスの一覧、architecture.md §13 の実測

**完了条件**：symphonia・md-5・gif・weezl・tungstenite が本番の依存から消え、png・miniz_oxide は直接の依存でなくなる／値が同じはずの読み手（FLAC・ALAC・PNG・GIF）が、ゴールデン・コーパス・差分のファズで旧実装と一致する／旧版の Vorbis・AAC で読んだ版をアンカーから作り直せる／NFR-14・NFR-15 を満たす
